# F-53 2부 — 일정 변경 공지 → 플래너 할 일·알림 (S22)

> 📝 기준: PRD v0.9 F-53·F-33 · API 명세 v0.4 7·9·10장 · ERD v0.9 3-2·5장 · 2026-10-18
>

> 1부를 먼저 합쳐야 패치가 붙는다. **마이그레이션 없음**

`schedule_change` 알림을 만든다. 1부에서 비워 둔 새 글 피드의 `planner_task_id`가 채워진다.

| 값 | 결과 |
| --- | --- |
| 시나리오 | **18/18 통과**(S22 새로 추가, 확인 23개) · 확인 합 243개 · 비용 0.011040 USD · LLM 8회 |
| 테스트 | **1327 passed**(DB 포함, 1부 1317 → +10) · DB 없이 1005 passed, 322 skipped |

| 마이그레이션 | 없음(`planner_tasks.lms_announcement_id`·알림 종류가 이미 있었다) |
| web | **바꾸지 않았다** — 플래너·알림함이 이미 이 모양을 읽는다 |

## 정한 것

1. **바뀌는 날은 분류 호출에서 함께 받는다.** 같은 공지를 두 번 읽히지 않으려고 `change_date`(YYYY-MM-DD)와
   `change_kind`(cancelled·room·time·other)를 같은 도구에 넣었다. 모델 호출 수는 1부와 같다(공지 하나에 한 번).
2. **날짜는 코드가 다시 본다.** 꼴이 틀리면 버리고, **게시일 기준** −1일 ~ +120일을 벗어나면 모델이 지어낸
   것으로 보고 버린다. 기준이 "지금"이 아니라 게시일인 이유는, 지난 공지를 늦게 분류해도 같은 값이 나와야
   하기 때문이다.
3. **날짜가 없거나 이미 지난 날이면 할 일을 만들지 않는다.** 무슨 날인지 모르는 할 일과 지난 휴강은 학생에게
   쓸모가 없다. 갈래·요약만 적고 끝낸다(알림도 만들지 않는다).
4. **할 일은 그 과목 수강생 모두에게.** 공지는 과목 공통 표라(ERD 3-2) 누가 동기화했든 수강생 전체의 플래너에
   들어간다 — 새 주차 자료 알림과 같은 모양이다. 연결을 끊은 사람은 뺀다.
5. **중복은 `not exists`로 막았다.** `(user_id, lms_announcement_id)`에 유일 인덱스가 없다. 인덱스를 만들면
   마이그레이션이 하나 더 생겨 네가 또 `db push`를 해야 한다 — 분류는 공지당 한 번이고 재시도 경로도 없어서
   지금은 조건 하나로 충분하다(아래 "남은 것"에 적었다).
6. **할 일 제목은 종류 이름이다** — `휴강`·`강의실 변경`·`수업 시간 변경`·`수업 일정 변경`. 과목 이름은
   할 일의 링크 칩에 따로 뜨니 제목에 넣지 않는다(명세 7장).
7. **고칠 수 있는 것은 완료 여부뿐이다.** 명세 7장의 `lms_announcement` 규칙이 이미 그랬고(제목·날짜는 LMS
   기준), S22가 `400 FIELD_READ_ONLY`까지 확인한다.
8. **알림은 찾은 때 바로 보낸다.** 다른 공고 알림처럼 다음 아침 09:00으로 미루면 휴강을 늦게 안다. 새 과제
   알림과 같은 방식이다. 키는 ERD 5장 표 그대로 `schedule_change:ann:{id}`이고, 알림을 끈 사람은 뺀다.
9. **일정 변경 알림 수는 실행 기록의 `notices`에 함께 센다.** API 응답(`GET /runs/{id}`)에는 새 칸을 만들지
   않았다 — 화면이 쓰지 않는 수를 늘리면 web 타입까지 따라 고쳐야 한다. 처리 과정에서는 `schedule_tasks`로
   따로 보인다.
10. **캘린더에는 넣지 않는다.** 휴강은 "없어진 수업"이라 Google 캘린더에 새 일정을 만들 일이 아니다. 수업
    일정 자체가 캘린더에 들어가는 기능(F-31 수업 시간표)이 생기면 그때 함께 정한다.

## 남은 것

- **유일 인덱스**: `planner_tasks (user_id, lms_announcement_id)`에 부분 유일 인덱스를 만들면 `not exists`
  없이도 중복이 막힌다. 마이그레이션이 하나 더 생기니 다음에 DB를 손볼 일이 있을 때 같이 넣는다.
- **F-54 자료 배포**: `material`로 분류된 공지에서 첨부를 받아 자료로 넣는 일. 공지 첨부 다운로드가 허용
  경로가 되어야 한다(명세 8장).
- **수업 시간표**: 휴강을 캘린더에서 지우는 일은 수업 일정 자체가 캘린더에 있어야 뜻이 있다(F-31).
- **공지 수정**: 휴강 날짜가 바뀐 공지는 다시 분류하지 않는다(1부와 같은 자리). S10과 함께 정한다.
