문서함(#68)은 받기 주소를 그 탭에서 열었다. 저장소가 `Content-Disposition: attachment`로 주니 화면은 그대로 두고 내려받기만
시작되는데, 서명한 뒤 저장소가 거절하면(그새 지워진 파일·저장소 오류) **브라우저가 저장소의 오류 JSON을 그 탭에 그대로

fetch로 받아 원래 이름으로 저장하고, 거절은 안내 문구로 바꿀 수 있다. 이 PR이 그것이다. API는 바뀌지 않는다.

## 정한 것

1. **받기는 fetch → Blob → `a[download]`다.** `GET /files/{id}/url`로 5분짜리 주소를 받는 것은 그대로이고, 그 주소를 열지 않고
   `fetch(url, { credentials: "omit", referrerPolicy: "no-referrer", cache: "no-store", signal: AbortSignal.timeout(120초) })`로
   받아 `file_name`으로 저장한다. 쿠키를 보내지 않아야 CORS `*`와 맞고(보내면 브라우저가 응답을 막는다, W5), 우리 주소(Referer)는
   저장소에 가지 않는다. 저장소가 주는 `Content-Disposition`의 이름은 쓰지 않는다 — CORS로는 그 머리값을 읽을 수 없고(노출
   머리값이 아니다), 화면이 이미 같은 이름(`file_name`·첨부 이름)을 안다.
2. **Blob 타입은 중립(`application/octet-stream`)이다.** 저장소가 준 `Content-Type`(공지 첨부는 HTML·SVG도 온다)을 그대로 쓰면
   blob: 주소가 우리 앱 출처라서, `download`를 무시하는 브라우저(일부 앱 안 브라우저)가 그 주소를 열 때 첨부의 HTML이 우리
   출처에서 돈다(검토가 찾은 것). 타입을 중립으로 두면 열리지 않고 저장만 된다. 무엇으로 열지는 이름의 확장자가 정한다.
3. **2분 안에 못 받으면 끊는다.** 저장소 연결이 멈추면(망 전환 등) 버튼이 "받는 중…"에 갇혀 새로고침 말고는 길이 없었다.
   `AbortSignal.timeout`으로 끊고 "파일을 받는 데 너무 오래 걸려요. 다시 눌러 주세요."를 보여 준다(20MB·느린 망을 생각해 2분).
4. **거절은 프론트 전용 코드 `DOWNLOAD_FAILED`(13장)로 화면에 간다.** `lib/saveFile.ts`의 `fetchDownload`가
   `DownloadFailed`를 내면 `documentsClient`가 `ApiError("DOWNLOAD_FAILED", 문구, 0)`로 바꿔서, 화면의 `errorMessage`가 그
   문구를 그대로 쓴다(5xx가 아니라 뭉뚱그리지 않는다). 문구 넷: 저장소가 거절 → "파일 저장소가 파일을 주지 않았어요. 잠시 후
   다시 눌러 주세요.", 본문 `code`가 `NoSuchKey`(서명한 뒤 지워짐) → "파일이 그새 없어졌어요. 다시 눌러 주세요."(다시 누르면
   서버가 404로 어디서 다시 받는지 알려 준다), 저장소에 닿지 못함 → "파일 저장소에 연결하지 못했어요. 잠시 후 다시 눌러
   주세요.", 기기가 오프라인 → "인터넷에 연결되어 있지 않아요. 연결을 확인하고 다시 눌러 주세요.", 2분 넘김 → 위 3.
5. **주소는 여전히 열쇠다.** 오류 문구·예외에 주소를 넣지 않고, 화면은 들고 있지 않는다. http(s)가 아닌 주소는 받지 않는다.
6. **`openDownload`는 지운다.** 쓰는 곳이 없다. CORS가 틀렸을 때 주소를 여는 방식으로 되돌아가는 비상구도 두지 않았다 —
   fetch의 실패는 CORS 거절과 오프라인·DNS 실패를 구별할 수 없어서, 비상구는 정확히 "브라우저 오류 화면이 앱을 덮는" 경우에
   켜진다(검토 권고). CORS는 운영 설정이라 합친 뒤 확인이 잡는다. `saveTextFile`은 `saveBlob` 위에 얹었다(.ics·목 모드가 그대로 쓴다).
7. **받기 주소의 `&download=`는 그대로 둔다.** 주소를 직접 열어도 원래 이름으로 받아지고(API 계약), 이번 변경은 화면 쪽뿐이다.
8. 20MB 첨부도 메모리에 한 번 올린다(Blob). 업로드 상한과 같은 크기라 괜찮다고 봤다.

## 합친 뒤 확인

````text
1. API·웹을 켜고 사이드바 "문서함" → 받기. 전처럼 원래 이름 그대로 받아지고 화면은 그대로여야 한다.
   브라우저 개발자 도구 Network에서 저장소 주소(…supabase.co/storage/v1/object/sign/…)로 간 요청이
   fetch(XHR)이고 200이면 된 것이다. 과목 상세 → 공지 탭의 "저장됨" 옆 받기도 같다.

2. 저장소가 **거절할 때도** CORS 머리값을 주는지 본다(10/19 확인은 200 응답뿐이었다. 거절에 없으면 "그새 없어졌어요"·
   "주지 않았어요" 대신 늘 "연결하지 못했어요"가 뜬다 — 다시 누르라는 안내라 치명적이진 않다). api 폴더에서 PowerShell에
   통째로 붙여 넣는다. 시험 파일(_check/ping.txt)만 쓰고 지운다. 주소는 열쇠라 찍지 않는다.

@'
import asyncio

import httpx

from app.config import get_settings
from app.uploads.storage import get_storage

PATH = "_check/ping.txt"


async def main() -> None:
    storage = get_storage(get_settings())
    await storage.upload(PATH, b"ping", "text/plain")
    url = await storage.signed_url(PATH, download_name="ping.txt")
    await storage.remove(PATH)  # signed, then gone: the link must now be refused
    async with httpx.AsyncClient(timeout=30) as client:
        got = await client.get(url, headers={"Origin": "http://localhost:3000"})
    print("refused ->", got.status_code, got.headers.get("content-type"))
    print("code ->", got.json().get("code") if "json" in (got.headers.get("content-type") or "") else None)
    print("cors on refusal ->", got.headers.get("access-control-allow-origin"))


asyncio.run(main())
'@ | uv run python -

이 모양이면 된 것이다(가짜 저장소에서 찍은 것. 실제는 상태 번호가 다를 수 있다 — 400·404 어느 쪽이든 code가 NoSuchKey면 같다).
refused -> 400 application/json
code -> NoSuchKey
cors on refusal -> *

cors on refusal이 None이면 그 세 줄을 보내 줘. 그러면 거절 안내 문구가 "연결하지 못했어요"로 합쳐지는 것뿐이라 고칠지는 그때 정한다.

3. 받기가 "파일 저장소에 연결하지 못했어요"로 실패하면 실제 Supabase의 CORS가 샌드박스 가정과 다른 것이다.
   그때는 개발자 도구 Console의 CORS 줄을 그대로 보내 줘 — 주소를 여는 방식(#68)으로 되돌리면 된다.
````

## 되돌림 시험

8가지를 일부러 고장 내고, 실제 모드로 다시 빌드해 브라우저 점검(가짜 저장소)으로 잡히는지 봤다. 전부 잡혔다. W7·W8은 검토 뒤
더한 것이다.

| # | 고장 낸 것 | 잡은 것 |
| --- | --- | --- |
| W1 | 거절(`!response.ok`)을 보지 않고 본문을 저장한다 | 저장소 500에 안내 대신 오류 JSON이 `.pdf`로 받아진다 |
| W2 | `NoSuchKey`를 따로 안내하지 않는다 | 서명 뒤 지워진 파일에 "그새 없어졌어요" 대신 뭉뚱그린 문구 |
| W3 | `download` 속성을 빼고 blob 주소를 연다 | 이름이 blob 번호(`….pdf`)가 되고 화면이 바뀐다 |
| W4 | `DownloadFailed`를 프론트 코드로 바꾸지 않는다 | 화면이 `errorMessage`의 기본 문구("파일을 받지 못했어요…")를 쓴다 |
| W5 | 쿠키를 같이 보낸다(`credentials: "include"`) | CORS `*`와 맞지 않아 브라우저가 막는다 — 받기가 안 된다 |
| W6 | 이름을 넘기지 않는다 | 빈 이름이라 blob 번호로 저장된다 |
| W7 | 저장소가 준 `Content-Type`을 그대로 Blob에 쓴다 | `createObjectURL`에 들어간 타입이 `application/pdf`다 |
| W8 | 시간 제한이 없다 | 저장소가 답을 안 주면 140초가 지나도 안내가 없다(받는 중에 갇힌다) |

## 검토에서 고친 것
