## 정한 것

1. **받기는 5분짜리 서명 주소에 `download=원래 이름`을 붙인 것이다.** 저장소가 `Content-Disposition: attachment`로
   내려보내서 브라우저가 열지 않고 받기만 한다(storage-js의 `download` 선택과 같은 방식). 공지 첨부는 형식을 가리지
   않고 받았으니(HTML·SVG도 온다) 저장소 도메인에서 그대로 열리면 안 된다. 이름은 `file_name`과 같다 — 올릴 때 이름이
   없으면 `파일.<확장자>`다.
2. **주소는 누를 때마다 새로 받는다.** 그 자체로 열쇠라 화면은 들고 있지 않고, 서버는 로그에 남기지 않으며, 응답에
   `Cache-Control: no-store`를 붙였다. 받은 주소는 같은 탭에서 열어도 attachment라 **화면이 바뀌지 않는다**(새 탭이 빈 채
   남지 않는다). 주소의 호스트는 언제나 우리 저장소다 — 저장소가 주는 것은 서명 경로뿐이고, 그것도
   `/object/sign/…?token=…` 꼴이 아니거나 `#`·빈칸·역슬래시가 섞이면 쓰지 않는다(`#` 뒤는 저장소에 가지 않아
   `download`가 빠진다).
3. **문서함에는 강의자료(공지 첨부 포함)와 강의계획서만 둔다.** 포스터는 공고 쪽에 있다. 포스터 번호로 받기를 부르면
   남의 파일과 똑같이 `404`다.
4. **과목은 내 과목 행일 때만 붙인다.** 공지 첨부는 받은 과목(`files.lms_course_id`), 계획서는 일정을 뽑을 때 고른 과목
   (`syllabi.lms_course_id`, 여러 번 뽑았으면 과목을 고른 마지막 것, 같은 시각이면 행 번호로)이다. 모르면 화면 맨 아래
   "과목을 정하지 않은 파일"에 모은다. 과목 묶음은 가장 최근 파일이 있는 과목부터다.
5. **지난 학기·수강을 뺀 과목도 묶음은 그대로 둔다.** 동기화가 `is_active`를 내린 과목은 과목 화면(9장)이 404라,
   응답의 `course.is_active`로 "과목 보기" 링크만 숨긴다. 파일은 그 과목 이름 아래에서 그대로 받는다.
6. **기록은 있는데 저장소에 파일이 없으면 `404`이고, 어디서 다시 받는지 알려 준다.** Supabase는 서명할 때 파일을 찾아보고
   없으면 `400 NoSuchKey`를 준다 → `StorageMissing`. 다시 눌러도 같으니 "잠시 후 다시"(502)가 아니다. 공지 첨부는
   "저장한 파일이 없어졌어요. LMS 공지에서 받아 주세요.", 올린 파일은 "…파일을 다시 올려 주세요."(받은 공지 첨부는
   기록이 남아 있어 동기화가 다시 받지 않는다). 단 **저장소 설정에 고칠 점이 있으면 이 답을 믿지 않는다** —
   publishable key처럼 권한이 모자란 키에도 저장소는 같은 `NoSuchKey`로 답해서, 그때 404를 주면 설정 문제가
   "파일이 없다"로 숨는다. 그때와 그 밖의 거절·연결 문제는 `502 STORAGE_API_ERROR`이고, 로그에는 저장소가 준 이유를 남긴다.
7. **목록은 1장 목록 규칙**(`limit` 1–50, 기본 20, cursor)이고 웹은 50개씩 받는다. 순서는 받은 순(최신 먼저), 같으면
   `file_id`. `files.created_at`에는 not null이 없어서 빈 행은 맨 뒤로 보낸다 — 행 하나 때문에 목록 전체가 깨지지
   않는다. 다른 목록의 cursor는 `422`(`details.fields.cursor`)이고 화면은 받아 둔 목록을 비우고 처음부터 다시 받는다.
   아주 깊게 겹친 JSON을 넣은 cursor는 읽다가 `RecursionError`로 500이 났다 — 공고 피드·LMS 새 소식·알림함이 같이 쓰는
   `decode_cursor`라 거기서 "잘못된 cursor"(422)로 바꿨다.
8. **응답 모델 이름은 `MyFile`·`MyFileList`·`MyFileCourse`다.** `DocumentItem`이 이미 공고 서류 타입이라 같은 이름이면 OpenAPI
   이름이 깨지고 web 타입도 겹친다.
9. **DB 연결은 파일을 찾을 때만 빌린다.** 저장소를 기다리는 동안 쥐고 있지 않는다(업로드와 같다).
10. **받기 실패는 화면 아래 안내로 알린다.** 404면 서버 문구, 그 밖에는 "파일을 받지 못했어요. 잠시 후 다시 눌러
    주세요." 받는 동안 버튼은 "받는 중…"이고 눌러도 지나간다 — `disabled`로 막으면 키보드 초점이 문서 맨 위로 튄다.
    공지 탭의 작은 받기도 누를 자리가 24px이고, "과목 보기"는 과목 이름까지 읽어 준다. 목 모드의 받기는 한 쪽짜리
    예시 PDF를 같은 이름으로 준다(PDF 보기 프로그램에서 열린다).
11. **이름을 줄일 때 확장자를 남긴다.** 이름은 200자까지인데, 그냥 자르면 `.pdf`가 떨어져 받은 파일을 열 프로그램을 못
    고른다. 업로드 때 저장하는 이름도 같은 함수(`clean_name`)라 같이 좋아진다.

독립 검토(새 에이전트, 읽기만)를 돌렸다. 큰 보안 문제는 없었고, 아래를 고친 뒤 시험·브라우저 점검·되돌림 시험을 다시 돌렸다.

| 본 것 | 고친 것 |
| --- | --- |
| **(버그)** 지난 학기·수강을 뺀 과목(`is_active` false)의 파일에도 "과목 보기"가 떠서, 누르면 과목 화면이 404로 빨간 상자만 보였다(검토자가 DB로 확인) | 묶음은 그대로 두고 `course.is_active`를 더해(명세에도 적음) 링크만 숨긴다 + DB 시험·목데이터에 지난 학기 과목 |
| **(버그)** 아주 깊게 겹친 JSON을 넣은 cursor가 500이었다. 공고 피드·LMS·알림함이 같이 쓰는 `decode_cursor`가 `RecursionError`를 놓쳤다 | 그것도 "잘못된 cursor"(422)로 + 시험 둘(문서함·피드). 처음 쓴 5,000겹 시험은 3.12에서 터지지 않아 되돌림 시험 D37이 살아남았다 → 2만 겹 |

## 남은 것

- **실제 Supabase의 받기 머리값은 아직 못 봤다** → 합친 뒤 확인 1. storage-api 코드와 storage-js가 쓰는 방식 그대로라
  다를 일은 적다.
- 받기 주소를 연 뒤 저장소가 실패하면(서명한 직후 파일이 지워짐·저장소 5xx) 브라우저가 저장소의 오류 JSON을 그 탭에
  연다. 서명할 때 파일을 확인하므로 드물다. 합친 뒤 확인의 cors가 `*`면 다음에 fetch로 받아 오류를 안내로 바꿀 수 있다.
- **탈퇴(#67)도 같은 사각지대가 있다**: publishable key처럼 권한이 모자란 키면 지우기도 `NoSuchKey`로 와서 "이미 없음"으로
  지나가고, 저장소에 파일이 남은 채 탈퇴가 끝날 수 있다. 저장소 설정에 고칠 점이 있으면 탈퇴를 멈추는 작은 PR이 필요하다
  (이번 범위 밖이라 안 건드렸다). 켤 때 설정 경고는 이미 뜬다.
- "더 보기"는 알림함과 같은 공용 버튼이라 불러오는 동안 `disabled`다(키보드 초점이 빠진다). 공용 버튼을 고치는 일은 따로.
- 시나리오 실행의 녹화 저장소(`RecordedStorage`)에는 받기 주소가 없다. 시나리오에 F-44가 없어서 지금은 쓰지 않는다.
- 포스터 원본 보기(`poster_url`, W6)와 강의자료 요약(F-15) 연결은 다음이다. 문서함에서 파일을 지우는 기능은 없다
  (탈퇴하면 지운다).
- 앞 PR의 남은 것(`%r` 로그 가리기, 변수 이름 `SUPABASE_SECRET_KEY`)은 그대로다.

### `GET /files` (P1)

문서함(F-44). 내 강의자료(공지 첨부 포함)와 강의계획서를 받은 순(최신 먼저)으로 준다. `?limit=20&cursor={next_cursor}`

```json
{
  "items": [
    { "file_id": "uuid", "file_name": "중간고사 대비 예제.pdf", "kind": "lecture_material", "origin": "lms_attachment", "course": { "id": "uuid", "short_name": "기계학습", "is_active": true }, "size_bytes": 1843200, "created_at": "2026-10-04T16:05:00+09:00" },
    { "file_id": "uuid", "file_name": "교양 강의계획서.pdf", "kind": "syllabus", "origin": "upload", "course": null, "size_bytes": 198656, "created_at": "2026-09-01T09:00:00+09:00" }
  ],
  "next_cursor": null
}
```

- 내 파일만 준다. 종류는 `lecture_material`(공지 첨부 포함)과 `syllabus`이고, 포스터는 공고 쪽에 있어 넣지 않는다
- `origin`은 `upload`(직접 올림)·`lms_attachment`(동기화가 받은 공지 첨부, F-54)다
- `course`는 **내** 과목이다. 공지 첨부는 받은 과목, 계획서는 일정을 뽑을 때 고른 과목(`syllabi.lms_course_id`, 여러 번 뽑았으면 과목을 고른 마지막 것)이고, 모르면 null이다. `short_name`은 9장 `GET /lms/courses`와 같다
- `course.is_active`는 그 과목을 지금 듣는지다. 지난 학기·수강을 뺀 과목은 false이고 과목 상세(9장)가 `404`라 화면은 과목 링크를 숨긴다. 파일은 그대로 그 과목에 묶인다
- `file_name`은 올릴 때 이름(`files.original_name`)이고, 없으면 `파일.<확장자>`다. `size_bytes`는 저장한 크기다
- 순서는 받은 순(최신 먼저)이고 같은 시각이면 `file_id`로 가른다. 쪽은 1장 목록 규칙대로 `limit` 1–50(기본 20)이다. 망가졌거나 다른 목록의 cursor는 `422 VALIDATION_FAILED`(`details.fields.cursor`)다
- 화면은 이 순서대로 과목끼리 묶고(가장 최근 파일이 있는 과목부터), 과목을 모르는 파일은 맨 아래에 모은다

### `GET /files/{file_id}/url` (P1)

그 파일을 5분 동안 받을 수 있는 주소(F-44). 화면은 "받기"를 누를 때마다 부르고 받은 주소를 바로 연다.

```json
{ "url": "https://{project}.supabase.co/storage/v1/object/sign/uploads/{경로}?token=…&download=%EC%A4%91%EA%B0%84…pdf", "expires_at": "2026-10-15T12:05:00+09:00" }
```

- 주소를 열면 파일 저장소가 `Content-Disposition: attachment`와 원래 이름(`file_name`)으로 내려보낸다(주소의 `download`). 공지 첨부는 형식을 가리지 않고 받아서(HTML·SVG도 올 수 있다) 브라우저에서 그대로 열지 않는다
- 주소는 그 자체로 열쇠다. 화면은 들고 있지 않고 서버는 로그에 남기지 않으며, 응답에 `Cache-Control: no-store`를 붙인다. `expires_at`은 주소를 만든 시각 + 5분이다(1장 파일 URL)
- 내 강의자료·계획서만 된다. 남의 파일·포스터·없는 번호는 `404 NOT_FOUND`, `file_id`가 UUID가 아니면 `422 VALIDATION_FAILED`다
- 기록은 있는데 저장소에 파일이 없으면(저장소가 `NoSuchKey`) `404 NOT_FOUND`이고, 다시 눌러도 같으니 어디서 다시 받는지 알려 준다: 공지 첨부는 "저장한 파일이 없어졌어요. LMS 공지에서 받아 주세요.", 올린 파일은 "…파일을 다시 올려 주세요." 단 서버의 저장소 설정에 고칠 점이 있으면(publishable key 등 — 그런 키에도 저장소는 `NoSuchKey`로 답한다) 이 답을 믿지 않고 `502 STORAGE_API_ERROR`다. 그 밖에 저장소가 주소를 주지 않으면(설정·연결 문제) `502 STORAGE_API_ERROR`다
- 주소의 호스트는 언제나 우리 Supabase 저장소다. 저장소가 서명 경로(`/object/sign/…?token=…`)가 아닌 것을 주면 쓰지 않고 `502`다

import { useCallback, useEffect, useRef, useState } from "react";
import { errorMessage, fieldErrors, getDocuments } from "@/api/client";
import type { MyFile } from "@/types/api";

// 문서함 목록 상태 (F-44). 첫 쪽을 받고 "더 보기"로 다음 쪽(cursor)을 이어 붙인다.
// 다음 쪽의 cursor가 맞지 않으면(422 details.fields.cursor) 받아 둔 목록을 버리고 처음부터 다시 받는다
export interface DocumentsState {
  items: MyFile[];
  loading: boolean;
  error: string | null;
  hasMore: boolean;
  loadingMore: boolean;
  reload: () => void;
  loadMore: () => void;
}

export default function useDocuments(): DocumentsState {
  const [items, setItems] = useState<MyFile[]>([]);
  const [cursor, setCursor] = useState<string | null>(null);
  const [loading, setLoading] = useState(true);
  const [loadingMore, setLoadingMore] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [round, setRound] = useState(0);
  const latest = useRef(0); // 늦게 온 응답은 버린다

  // 첫 쪽. 다시 받는 동안 이미 받은 목록은 그대로 둔다(빈 화면이 번쩍이지 않게)
  useEffect(() => {
    const token = (latest.current += 1);
    setLoading(true);
    setError(null);
    setLoadingMore(false);
    getDocuments()
      .then((page) => {
        if (token !== latest.current) return;
        setItems(page.items);
        setCursor(page.next_cursor);
        setLoading(false);
      })
      .catch((cause: unknown) => {
        if (token !== latest.current) return;
        setError(errorMessage(cause, "문서함을 불러오지 못했어요. 잠시 후 다시 시도해 주세요."));
        setLoading(false);
      });
  }, [round]);

  const reload = useCallback(() => setRound((value) => value + 1), []);

  const loadMore = useCallback(() => {
    if (!cursor || loadingMore || loading) return;
    const token = latest.current;
    setLoadingMore(true);
    getDocuments(cursor)
      .then((page) => {
        if (token !== latest.current) return;
        setLoadingMore(false);
        setItems((current) => [...current, ...page.items]);
        setCursor(page.next_cursor);
        setError(null);
      })
      .catch((cause: unknown) => {
        if (token !== latest.current) return;
        setLoadingMore(false);
        // 다시 받다가 실패해도 "다시 시도"가 보이게 받아 둔 목록을 비운다(빈 화면 안내가 그 버튼을 준다)
        if (fieldErrors(cause).cursor) {
          setItems([]);
          setCursor(null);
          reload();
          return;
        }
        setError(errorMessage(cause, "문서함을 더 불러오지 못했어요. 다시 눌러 주세요."));
      });
  }, [cursor, loading, loadingMore, reload]);

  return { items, loading, error, hasMore: cursor !== null, loadingMore, reload, loadMore };
}
