## 정한 것

1. **`Button`에 `busy`를 더한다.** `disabled`는 "지금은 할 수 없는 일"(입력이 덜 됐다 등)로 그대로 두고, `busy`는 "누른 일이 진행
   중"이다. busy면 `aria-disabled="true"`·`aria-busy="true"`를 달고 **click을 취소**(`preventDefault`)해서 눌러도 지나가며,
   `disabled`가 아니라 초점이 남는다. click을 취소해야 `type="submit"`일 때 폼 제출(입력란에서 Enter도 그 버튼의 click이다)까지
   막힌다(검토). 모양은 `aria-disabled:cursor-wait aria-disabled:opacity-45 aria-disabled:active:scale-100`(disabled와 같은 흐림,
   `DownloadButton`과 같은 커서, 눌림 효과 없음). `disabled`와 `busy`를 같이 주지 않는다(둘 다면 disabled가 이겨 초점이 빠진다).
2. **두 "더 보기"만 `busy`로 바꾼다.** `useDocuments`·`useNotifications`의 `loadMore`가 `loadingMore`면 이미 지나가므로 두 겹이다.
   다른 `disabled={saving}` 버튼들(저장·동의·연결 등)은 이번에 손대지 않았다(남은 것).
3. **마지막 쪽이 오면 버튼이 사라져 초점이 `<body>`로 간다.** 이번 범위 밖이다(남은 것에 가장 작은 고침을 적었다).
4. **web/CLAUDE.md "하지 않는 것"에 규칙 한 줄**: 진행 중인 버튼을 `disabled`로 막지 않고 `busy`를 쓴다. 같은 패턴이 20곳 넘게
   있어서 규칙이 없으면 새 코드도 계속 그렇게 간다(검토). 문서함 PR의 "남은 것"(더 보기 초점)은 이 PR로 닫힌다 — 옛 기록은 관례대로
   그대로 둔다.

## 검토에서 고친 것

독립 검토(새 에이전트, 읽기만)에서 꼭 고칠 것은 없었다. React 19가 `aria-disabled={true}`를 `"true"`로, `undefined`를 속성 없음으로
내는 것, Tailwind 4의 `aria-disabled:` 변형이 내장이고 레포가 이미 쓰는 것(DownloadButton·Pager·관심 공고 버튼), 두 훅이
`loadingMore`를 막는 것, 연타는 첫 클릭의 상태가 동기 반영되어 두 번째 클릭 때 이미 막혀 있는 것을 확인했다.

| 본 것 | 고친 것 |
| --- | --- |
| `onClick`만 빼면 `type="submit"` 버튼은 못 막는다 — 클릭의 기본 동작이 제출이고, 입력란에서 Enter도 기본 버튼의 click이다. 다음에 `busy`로 바꿀 후보(프로필 저장 둘)가 submit이라 그 폼이 두 번 보낼 수 있었다 | 핸들러를 늘 달고 busy면 `preventDefault`로 click을 취소한다(제출까지 막힌다). 주석에도 적었다 |
| `busy`를 말하는 규칙이 없어 `disabled={saving}` 패턴(20곳 넘게)이 계속 늘 수 있다 | web/CLAUDE.md "하지 않는 것"에 한 줄 |
| busy인데 hover·눌림 효과가 산다 | `aria-disabled:active:scale-100`(hover 배경은 두었다 — DownloadButton과 같다) |
| `disabled`와 `busy`를 같이 주면 disabled가 이긴다 | 주석에 "같이 주지 않는다" |

그대로 둔 것

| 제안 | 판단 |
| --- | --- |
| 초점이 남은 버튼의 글이 "불러오는 중…"으로 바뀌는 것을 스크린리더가 늘 읽지는 않는다 — 늘 두는 `sr-only` `role="status"`("다음 쪽을 불러오고 있어요" → "N개를 더 불러왔어요") | 전보다 나쁜 게 없고 DownloadButton과 같은 수준이라 두었다. 마지막 쪽 초점 고침과 묶어서 한다(남은 것) |
| `DownloadButton`은 쉴 때 `aria-disabled="false"`를 내고 Button은 속성이 없다 | 둘 다 유효하고 동작 차이가 없다. 나중에 DownloadButton을 맞춘다 |

## 남은 것

- **마지막 쪽이 오면 버튼이 사라져 초점이 `<body>`로 간다.** 가장 작은 고침은 "더 보기"가 사라질 때 새로 온 첫 항목의 받기
  버튼(문서함)·첫 알림(알림함)으로 초점을 옮기는 것이다. 화면마다 ref가 필요해 따로 한다.
- `disabled={saving}`처럼 "누른 일이 진행 중"인데 `disabled`로 막는 버튼이 더 있다. 같은 자리에 남아 다시 누를 수 있는 곳이
  문제다(검토가 정리한 목록): 플래너 `.ics 내려받기`(`disabled={downloading}`, 1순위), `DeadlineCalendarRow` 캘린더에 넣기·빼기,
  `MaterialSummaryPanel` 번역하기(`selected.length===0`은 disabled로 두고 `translating`만 busy로), `PlannerDayPanel` 할 일 체크박스
  (체크마다 초점이 날아간다 — 체크박스는 aria-disabled가 토글을 못 막아 `onChange`에서 무시), `PreparationProgress` 완료,
  `IncomeConsentSetting` 스위치·철회, `BrowserPushSetting`/`Toggle`(`denied`는 진짜 disabled), `SyllabusConfirmedList` 캘린더에
  넣기(누른 줄만), 알림함·알림 패널 "모두 읽음"(누르는 순간 unread가 0이 되어 disabled → 초점이 빠진다). 성공하면 화면이 바뀌는
  곳(로그인·연결하기·포스터 등록·온보딩 단계·계획서 확정·탈퇴·프로필 저장 둘)은 후순위다. 프로필 저장 둘은 submit이라 폼
  `onSubmit`도 `saving`을 봐야 한다.
- 마지막 쪽 초점 고침(검토가 적은 가장 작은 방법): 누를 때 마지막 항목 id를 기억 → 다음 쪽이 오고 `hasMore`가 꺼지면 그다음 항목의
  줄(`tabIndex={-1}`)로 `.focus()`, 같은 effect에서 `sr-only` status 문구도 바꾼다. 문서함에서 cursor 422로 처음부터 다시 받을 때도
  버튼이 사라지므로 같이 본다.
- `type="submit"` 버튼에 `busy`를 쓰면 입력란에서 Enter로 보내는 것(암묵적 제출)은 막지 못한다. 지금 `busy`를 쓰는 곳은 둘 다
  `type="button"`이다.
