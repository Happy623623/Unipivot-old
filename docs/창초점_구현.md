# 창(Modal) 초점 구현 (web, `fix/web-modal-focus`)

> 📝 기준: web/CLAUDE.md · 포스터원본보기·더보기마지막초점·busy전환 문서의 "남은 것"(세 번의 독립 검토가 모두 짚은 것)
> 적용할 곳: #77까지 합친 `main`(d16d008) 위. 샌드박스에서 그 커밋 위에 그대로 만들고 시험했다.

공용 창 `components/Modal.tsx`는 `role="dialog"`·`aria-modal`만 있고 초점을 다루지 않았다. 창을 열어도 초점이 뒤 화면에 남고, Tab이 창 밖(뒤 화면, 바깥 덮개 버튼)으로 나가고, Esc로 닫히지 않고, 닫으면 초점이 `<body>`로 떨어졌다. 이 PR은 새 훅 `lib/useDialogFocus.ts`로 이 넷을 고친다. 창 아홉 군데(탈퇴·프로필 수정·소득 동의 철회·캘린더/LMS 연결 해제·LMS 연결·정보 입력·그래도 준비하기·일정 추가/수정·공고 신고·포스터 원문)가 모두 이 `Modal`을 써서 한 곳만 고친다. 사용자가 고른 작업이고(권장), 세부는 아래 "정한 것"이다.

## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 열면 **창 자체**(`tabIndex={-1}`)로 초점 | 화면 읽기 프로그램이 창 이름(`aria-label`)을 먼저 읽는다. 첫 버튼으로 바로 보내는 안은 탈퇴·연결 해제처럼 되돌릴 수 없는 창에서 Enter 한 번으로 실행될 위험이 있어 버렸다. 창 안에서 스스로 초점을 잡은 조각이 있으면 그대로 둔다 |
| Tab·Shift+Tab은 창 안에서 돈다 | 처음·끝 초점 가능 요소 사이를 돈다. 창 자체나 목록에 없는 곳(포스터 원문 창의 `tabIndex=-1` 상자 등)에서는 Tab이면 처음, Shift+Tab이면 끝으로(검토). 보이지 않는 요소와 `disabled`는 건너뛴다 |
| Esc = 닫기 버튼 | 각 창의 `onClose`를 그대로 부른다(저장 중에도 닫기 버튼과 같다). 단 한글 조합 중 Esc(`isComposing`·keyCode 229), 다른 곳이 이미 처리한 Esc(`defaultPrevented`), `<select>`에서 누른 Esc(펼친 목록을 접는 Esc가 창까지 닫는 브라우저가 있다)는 닫지 않는다(검토) |
| 닫히면 **연 버튼**으로 | 열 때 초점이 있던 요소를 기억한다. 그 요소가 사라졌으면 `Modal`의 `returnFocusRef`(대신 돌아갈 곳)로, 그것도 없거나 사용자가 이미 다른 곳에 있으면 돌려주지 않는다. 플래너 할 일의 "⋯" 메뉴에서 연 창은 메뉴 항목이 사라지므로 "⋯" 버튼을 `returnFocusRef`로 준다(검토). 소득 동의 철회처럼 끝나면 저절로 닫히는 창도 스위치로 돌아온다(busy전환 문서 "남은 것") |
| 창 이름은 `aria-labelledby`로 제목(h2)을 가리킨다 | 전에는 `aria-label`과 h2가 같은 글을 따로 들고 있었다(검토) |
| 창이 여러 개면 맨 위 창만 키·초점을 맡는다 | 열린 창을 쌓아 두고 맨 위만 처리한다. 지금은 창 안에서 창을 여는 곳이 없지만, 생기면 두 창의 `focusin`이 서로 초점을 끌어가는 것을 막는다(검토) |
| 초점이 창 밖으로 나가면 창으로 되돌린다(`focusin`) | `aria-modal`을 지키지 않는 브라우저·화면 읽기 프로그램 대비. 뒤 화면 전체에 `inert`를 거는 안은 앱 틀(AppShell) 구조를 건드려야 해서 버렸다 |
| 바깥 덮개 버튼은 `tabIndex={-1}`·`aria-hidden` | 마우스로 바깥을 눌러 닫는 것은 그대로 두고, 키보드 순서·화면 읽기에서는 뺀다(Esc와 닫기 버튼이 있다). 전에는 Tab이 이 "모달 닫기" 덮개로 갔다 |
| 훅은 `src/lib`에 | DOM 일(`focus`, `addEventListener`)은 `src/lib`에 둔다는 규칙 |

## 8. 남은 것

- 헤더 알림 패널(`NotificationPanel`)은 `Modal`이 아니라 옆에서 나오는 판이라 이번에 손대지 않았다. → 10/20 같은 훅(`useDialogFocus`)을 쓰게 했다(docs/알림패널초점_구현.md).
- 뒤 화면에 `inert`를 걸지 않아 화면 읽기 프로그램의 가상 커서는 뒤 화면을 읽을 수 있다(`aria-modal`에 맡긴다).
- 저장·탈퇴가 진행 중일 때도 Esc로 닫힌다(닫기 버튼·덮개도 전부터 그랬다). 닫힌 뒤 실패하면 오류가 닫힌 창 안에 그려져 안 보인다 — 진행 중엔 닫기를 막을지 따로 정한다.
- 창에 초점을 줄 때 제목만 읽히고 본문(탈퇴 경고 등)은 자동으로 읽히지 않는다(`aria-describedby` 없음).
- 알림 패널에서 바로 연 정보 입력 창 등 연 버튼이 없는 창은 닫혀도 초점이 돌아갈 곳이 없다.
- 창이 열린 동안 토스트의 동작 버튼에는 키보드로 갈 수 없다(지금은 창과 동작 토스트가 함께 뜨는 흐름이 없다).

## 10. 코드와 패치

### 코드 (새 파일)

#### `web/src/lib/useDialogFocus.ts`

````ts
import { useEffect, useRef, type RefObject } from "react";

// 창(components/Modal.tsx)의 키보드 초점.
// 열리면 창으로 초점을 옮기고(창 자체 — 제목을 읽고, 탈퇴처럼 되돌릴 수 없는 버튼에 바로 가지 않게),
// Tab·Shift+Tab은 창 안에서 돌고, Esc는 닫기와 같고, 닫히면 연 버튼으로 초점을 돌려준다.
// 연 버튼이 그새 사라졌으면(메뉴 안의 버튼 등) fallback(메뉴를 연 버튼 등)으로, 그것도 없거나 사용자가 이미 다른 곳에
// 있으면 돌려주지 않는다. 창이 여러 개 열리면 맨 위(나중에 연) 창만 키와 초점을 맡는다
const FOCUSABLE = [
  "a[href]",
  "button:not([disabled])",
  "input:not([disabled]):not([type='hidden'])",
  "select:not([disabled])",
  "textarea:not([disabled])",
  "[tabindex]:not([tabindex='-1'])",
].join(",");

const openDialogs: HTMLElement[] = []; // 열린 창, 나중에 연 것이 끝

function focusables(root: HTMLElement): HTMLElement[] {
  return [...root.querySelectorAll<HTMLElement>(FOCUSABLE)].filter((element) => element.getClientRects().length > 0);
}

// Esc를 창 닫기로 보지 않는 때: 한글 조합 중(조합 취소), 다른 곳이 이미 처리함, 펼친 select를 접는 Esc(브라우저마다 다르다)
function escapeBelongsElsewhere(event: KeyboardEvent): boolean {
  return event.isComposing || event.keyCode === 229 || event.defaultPrevented || event.target instanceof HTMLSelectElement;
}

export default function useDialogFocus(
  dialogRef: RefObject<HTMLElement | null>,
  open: boolean,
  onClose: () => void,
  fallbackRef?: RefObject<HTMLElement | null>,
) {
  const close = useRef(onClose);
  useEffect(() => {
    close.current = onClose;
  }, [onClose]);

  useEffect(() => {
    const dialog = dialogRef.current;
    if (!open || !dialog) return;
    const doc = dialog.ownerDocument;
    const active = doc.activeElement;
    const opener = active instanceof HTMLElement && active !== doc.body && !dialog.contains(active) ? active : null;
    openDialogs.push(dialog);
    const isTop = () => openDialogs[openDialogs.length - 1] === dialog;
    if (!dialog.contains(doc.activeElement)) dialog.focus({ preventScroll: true });

    const onKeyDown = (event: KeyboardEvent) => {
      if (!isTop()) return;
      if (event.key === "Escape") {
        if (escapeBelongsElsewhere(event)) return;
        event.preventDefault();
        close.current();
        return;
      }
      if (event.key !== "Tab") return;
      const items = focusables(dialog);
      const current = doc.activeElement as HTMLElement | null;
      if (items.length === 0) {
        event.preventDefault();
        dialog.focus();
        return;
      }
      const first = items[0];
      const last = items[items.length - 1];
      const listed = current !== null && items.includes(current);
      // 창 자체나 목록에 없는 곳(tabIndex=-1 상자 등)에 있으면 처음·끝으로 보낸다(브라우저가 창 밖으로 보내지 않게)
      if (!listed) {
        event.preventDefault();
        (event.shiftKey ? last : first).focus();
      } else if (event.shiftKey && current === first) {
        event.preventDefault();
        last.focus();
      } else if (!event.shiftKey && current === last) {
        event.preventDefault();
        first.focus();
      }
    };
    // 화면 읽기 프로그램이나 스크립트가 초점을 창 밖으로 옮기면 창으로 되돌린다(aria-modal을 지키지 않는 브라우저 대비)
    const onFocusIn = (event: FocusEvent) => {
      if (isTop() && event.target instanceof Node && !dialog.contains(event.target)) dialog.focus({ preventScroll: true });
    };
    dialog.addEventListener("keydown", onKeyDown);
    doc.addEventListener("focusin", onFocusIn);
    return () => {
      dialog.removeEventListener("keydown", onKeyDown);
      doc.removeEventListener("focusin", onFocusIn);
      openDialogs.splice(openDialogs.indexOf(dialog), 1);
      const now = doc.activeElement;
````
