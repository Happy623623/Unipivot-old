1. **창 설명**: 되돌릴 수 없는 일을 묻는 창(탈퇴, 두 연결 해제, 소득 동의 철회, 그래도 준비하기)을 열면 제목만 읽히고 경고는 읽히지 않았다.

4. **로그인 안내**: 로그아웃·탈퇴·만료 안내를 화면을 열 때부터 그려서, 화면 읽기 프로그램이 읽지 않았다.
5. **정보 입력 창**: 알림함·푸시·주소로 바로 연 정보 입력 창은 연 버튼이 없어서, 닫아도 초점이 돌아갈 곳이 없었다.

## 1. 정한 것 (사용자 부재 — 모두 권장안)

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 창 설명은 `ModalDescription` 하나로 | 경고 글을 `<ModalDescription>`으로 감싸면 창에 `aria-describedby`가 붙는다. 다섯 창만 쓴다. 입력 안내처럼 길거나 바뀌는 글에는 쓰지 않는다(검토가 다른 창에는 되돌릴 수 없는 경고가 없다고 확인). `description` prop 안은 창마다 글 모양이 달라 버렸다 |
| `aria-describedby`는 레이아웃 단계에서 창에 직접 붙인다 | 처음엔 상태로 붙였는데, 그러면 창에 초점이 간 **다음** 그리기에서야 붙어 처음 읽을 때 경고를 놓칠 수 있었다(검토). 레이아웃 단계는 초점을 옮기는 효과보다 먼저 돈다. 창은 자기 글 요소에서 `closest('[role="dialog"]')`로 찾는다(처음 그릴 때 자식의 레이아웃 단계에는 창의 ref가 아직 없다). 늘 붙여 두는 안은 가리키는 요소가 없을 때 검사 도구가 경고해서 버렸다 |
| 사라지는 버튼의 초점은 그 자리의 결과 글로(`useFocusHandoff`) | `mark(key)`는 누를 때 부르는데, 그때 초점이 화면 안에 있었을 때만 기억한다(Safari에서 마우스로 누르면 초점이 없어 옮기지 않는다 — 다른 초점 처리와 같은 규칙). `target(key)`은 새로 생긴 글의 ref다. 생기는 순간 초점이 `<body>`면 그 글(`tabIndex=-1`)로 옮긴다. 넣지 못하고 끝나면 기억을 지운다(검토). 토스트도 같은 글을 읽어 두 번 읽힐 수 있는데, 그대로 둔다 |
| 플래너 "삭제": 할 일마다 잠그고 "지우는 중" | 두 번째 요청이 "없는 일정"으로 실패해 오류가 떴다. `busy` 규칙과 같다(`aria-disabled`·`aria-busy`, 누름 무시). 메뉴는 그 할 일의 메뉴일 때만 닫는다(그새 연 다른 메뉴는 둔다, 검토) |
| 지운 뒤 초점: "⋯"(실패해 남았으면), 아니면 날짜 제목 | 다시 그린 **뒤에** 맞춘다. 그리기 전에 보면 초점이 아직 "지우는 중"에 있어서 놓칠 수 있었다(검토). 누를 때 초점이 없었으면(마우스·Safari) 옮기지 않는다 |
| 로그인 안내는 빈 live 영역을 먼저, 글은 150ms 뒤(`useLateAnnouncement`) | live 영역은 바뀐 내용만 읽는다. 감싼 div에는 여백이 없어 배치는 같다. 지연을 300~500ms로 늘릴지는 실기기 화면 읽기 프로그램으로 확인한 뒤 정한다(8장) |
| 정보 입력 창의 돌아갈 곳은 "AI 자격 판정" 제목 | 알림함 화면·푸시·주소로 `?focus=profile_input`을 바로 열면 연 버튼이 없다. 판정 결과가 바로 그 아래라 닫고 나서 볼 곳이다. 헤더 알림 패널에서 열면 연 버튼이 종이라 종으로 간다(검토 — 그대로) |
| 초점을 받는 제목·글에도 초점 테두리 | `outline-none`만 두면 키보드로 왔을 때 표시가 없다(검토). 다른 곳과 같은 `focus-visible:outline-[#4f6ef7]` |
| 새 API·기준 문서 변경 없음 | 앞 구현 기록 넷의 "남은 것" 줄만 고친다(9장). web/CLAUDE.md 두 줄은 패치에 들어 있다 |

| A6 지운 뒤 후보 순서를 바꿈(제목 먼저) | 삭제 실패: 할 일이 남고 초점은 '⋯'로 |

## 7. 검토에서 고친 것

새 에이전트가 읽기만 하고 검토했다.

| 지적 | 처리 |
| --- | --- |
| (중간) `aria-describedby`가 상태로 붙어서, 창에 초점이 간 다음 그리기에서야 생긴다. 처음 읽을 때 경고를 놓칠 수 있다 | 레이아웃 단계에서 창에 직접 붙인다. 초점이 가는 순간을 기록하는 점검을 더했다(A3) |
| (중간) 지운 뒤 초점을 다음 프레임에 맞추면, 다시 그리기 전일 때 초점이 아직 "지우는 중"에 있어 놓친다(가끔) | 다시 그린 뒤 효과에서 맞춘다(`refocus`) |
| (낮음) 실패하면 `useFocusHandoff`의 기억이 남는다. 나중에 다른 길로 "넣었어요"가 되면 초점을 가져갈 수 있다 | 진행이 끝나면(`busyItem === null`) `cancel()` |
| (낮음) 지우는 동안 다른 할 일의 메뉴를 열면 끝날 때 그 메뉴가 닫힌다 | 그 할 일의 메뉴일 때만 닫는다 |
| (낮음) 지운 뒤 초점은 누를 때 초점이 있었는지 보지 않는다(Safari 마우스) | 누를 때 초점이 있었을 때만 옮긴다(A7) |
| (낮음) 초점을 받는 제목·글에 초점 테두리가 없다 | `focus-visible` 테두리 |

#### `web/src/lib/useFocusHandoff.ts`

````ts
import { useCallback, useRef } from "react";

// 누른 버튼이 일이 끝나 다른 것으로 바뀌어 사라질 때(예: "캘린더에 넣기" → "캘린더에 넣었어요"), 초점이 <body>로
// 빠져 키보드·화면 읽기 사용자가 자리를 잃지 않게 그 자리에 새로 생긴 것으로 넘긴다.
// mark(key): 누를 때 부른다. 그때 초점이 화면 안에 있었을 때만 기억한다(마우스로 눌러 초점이 없으면 옮기지 않는다).
// target(key): 새로 생긴 요소의 ref로 준다. 생기는 순간 초점이 <body>에 있으면(버튼이 사라져서) 그 요소로 옮긴다.
// 요소에는 tabIndex={-1}을 준다(읽기 전용 글이라 Tab 순서에는 넣지 않는다)
export default function useFocusHandoff() {
  const pending = useRef<string | null>(null);

  const mark = useCallback((key: string) => {
    const active = document.activeElement;
    pending.current = active && active !== document.body ? key : null;
  }, []);

  const target = useCallback(
    (key: string) => (element: HTMLElement | null) => {
      if (!element || pending.current !== key) return;
      pending.current = null;
      if (document.activeElement === document.body || document.activeElement === null) {
        element.focus({ preventScroll: true });
      }
    },
    [],
  );

  const cancel = useCallback(() => {
    pending.current = null;
  }, []);

  return { mark, target, cancel };
}

// 다음 그리기 뒤에, 초점이 <body>로 빠졌으면(누른 것이 사라짐) 후보 중 아직 화면에 있는 첫 요소로 옮긴다.
// 후보는 그때 읽도록 함수로 받는다(ref는 다시 그린 뒤에 바뀐다)
export function focusIfLost(candidates: () => (HTMLElement | null | undefined)[]): void {
  requestAnimationFrame(() => {
    if (document.activeElement !== document.body && document.activeElement !== null) return;
    candidates()
      .find((element) => element?.isConnected)
      ?.focus({ preventScroll: true });
  });
}
````

#### `web/src/lib/useLateAnnouncement.ts`

````ts
import { useEffect, useState } from "react";

// 화면을 열 때부터 들어 있는 안내는 화면 읽기 프로그램이 읽지 않는다(live 영역은 바뀐 내용만 읽는다).
// 그래서 빈 영역(role="status"·"alert")을 먼저 그리고, 조금 뒤에 글을 넣는다. 글이 바뀌면 다시 늦춰 넣는다
const DELAY_MS = 150;

export default function useLateAnnouncement(text: string | null): string | null {
  const [shown, setShown] = useState<string | null>(null);

  useEffect(() => {
    setShown(null);
    if (!text) return;
    const timer = setTimeout(() => setShown(text), DELAY_MS);
    return () => clearTimeout(timer);
  }, [text]);

  return shown;
}
````
