> 📝 기준: API 명세 v0.4 12장 · PRD v0.9 F-11 · 2026-10-19

> 적용할 곳: **스케줄러(#59)까지 합친 main** 위 새 브랜치. **마이그레이션 없음**

PRD 체크리스트에 "청년정책 정기 수집 — `/internal/jobs/fetch-policies`와 스케줄러, 배포 때"로 남아

`python -m app.youth.cli fetch`를 쳐야 새 정책이 들어왔다. 스케줄러가 생겼으니 그 위에 올렸다.

## 정한 것

1. **명령과 같은 함수를 부른다.** `app/youth/importer.collect` 하나를 명령(`app.youth.cli`)·엔드포인트·
   스케줄러가 같이 쓴다. 숫자(새 공고·바뀐 공고·그대로·만료·숨김·가져오지 않음)도 명령이 찍는 것과
   같다.
2. **매일 KST 04:00이다.** 공고 알림 예약이 08:30이라 그 전에 끝나야 그날 새 정책이 그날 예약에
   들어간다. 처음 넣을 때 1~3분 걸리고 온통청년을 최대 600번 부르는 일이라 새벽에 뒀다.
3. **서버를 켤 때는 돌리지 않는다.** `--reload`로 서버가 다시 뜰 때마다 온통청년을 600번 부르면
   안 된다. 밀린 수집은 다음 04:00에 따라잡는다 — 정책은 하루 늦어도 큰일이 아니다.
4. **`YOUTH_API_KEY`가 없으면 작업을 목록에 넣지 않는다.** 매일 502를 로그에 남기는 대신, 켤 때
   경고 한 줄로 끝낸다. 엔드포인트를 손으로 부르면 502 `YOUTH_API_ERROR`다(13장에 있는 코드).
5. **수집은 자기 연결을 새로 연다.** 정책마다 트랜잭션으로 묶어 넣는 일이라 **autocommit** 연결이어야
   하는데, 요청 풀은 트랜잭션 연결이다. 명령이 하는 것과 같이 열고 닫는다(`connect_timeout` 10초).
6. **응답 모양은 명령 출력을 그대로 옮겼다.** `fetched`·`total`·`complete`·`stopped`·`new`·`updated`·
   `unchanged`·`expired`·`hidden`·`skipped`·`gone_kept`. 명세 12장에 적었다.
7. **온통청년 오류는 502로, 실행 기록은 실패로 남긴다.** `collect`가 실행을 실패로 적고 올리는
   것을 그대로 두고, 라우터에서 `YOUTH_API_ERROR`로 바꾼다.
8. **클라이언트 공장을 의존으로 뺐다**(`app/youth/deps.py`). 시험이 가짜 온통청년으로 바꿔 끼운다 —
   명령 시험이 `make_client`로 하던 것과 같은 자리다.

## 되돌림 시험

9가지를 일부러 고장 내고 시험이 잡는지 봤다. 전부 잡혔다.

| # | 고장 낸 것 | 잡은 시험 |
| --- | --- | --- |
| M1 | 온통청년 오류를 502로 바꾸지 않는다 | DB — 502 확인 |
| M2 | 키가 비어도 돌린다 | 단위 — 키 없이 502 |
| M3 | 다 쓴 클라이언트를 닫지 않는다 | DB — `closed` 확인 |
| M5 | 키가 없어도 수집을 목록에 넣는다 | 단위 — 작업 셋 |
| M6 | 수집을 예약 뒤(09:00)로 민다 | 단위 — `FETCH_AT < SCHEDULE_AT` |
| M7 | 수집을 서버 켤 때 바로 돌린다 | 단위 — `at_start` |
| M9 | 가져오지 않은 정책 수를 세지 않는다 | DB — `skipped 1` |
| M10 | 받은 정책 수를 세지 않는다 | DB — `fetched 3` |
| M12 | 스케줄러가 키 없이 부른다 | DB — 스케줄러 줄 결과 |

(M4·M8·M11은 뺐다 — 연결을 닫지 않는 것, 날짜를 KST로 바꾸지 않는 것, 라우터 의존 꼬임은 지금
시험으로 못 잡는다. 아래 "남은 것"에 적었다.)

## 검토에서 고친 것

| 본 것 | 고친 것 |
| --- | --- |
| DB 시험이 혼자서는 통과하는데 전체에서는 깨졌다 — 실패한 실행을 "시작 시각 뒤의 batch_crawl 전부"로 골라서 **다른 시험의 실행**이 섞였다 | 502 전후의 실행 집합 차로 내 실행 하나만 고르고, 지울 때도 id로만 지운다 |
| 단위 시험이 DB 없이 돌 때 모든 요청이 503이었다 — `get_log_connect` 의존이 풀이 없으면 먼저 거절한다 | 시험 앱에 연결하지 않는 DB 주소를 줘서 풀만 만들게 했다(`test_internal_api.py`와 같은 방식) |

## 남은 것

- **연결을 닫지 않는 고장은 시험이 못 본다.** `fetch_policies_fresh`가 `finally`에서 닫지만, 닫지
  않아도 시험은 통과한다. `pg_stat_activity`를 세는 시험은 다른 시험과 섞여 흔들려서 넣지 않았다.
- **빠짐없이 받지 못한 날은 목록에서 사라진 정책을 숨기지 않는다**(명령과 같다). 며칠 연속 그러면
  내려간 정책이 남는다 — 명령의 `--hide-gone`은 엔드포인트에 없다. 필요해지면 쿼리 값으로 더한다.
- 명세 12장의 `crawl-notices`·`crawl-contests`·`expire-opportunities`는 아직 엔드포인트가 없다.
  `expire-opportunities`는 지금 필요가 없다 — 피드(`_ACTIVE`)와 상세가 마감을 직접 보고 숨긴다.

## 코드

새로 만드는 파일 4개다.

#### `api/app/schemas/youth.py`

```python
"""청년정책 수집 작업의 응답 (API 명세 12장 `POST /internal/jobs/fetch-policies`)."""

from pydantic import BaseModel


class FetchPoliciesResult(BaseModel):
    """수집 한 번의 결과. 명령 `python -m app.youth.cli fetch`가 찍는 숫자와 같다.

    `fetched`는 받은 정책 수, `total`은 온통청년이 말한 전체 수다. `complete`가 false면 빠짐없이
    받지 못한 것이고, 그때는 목록에서 사라진 정책을 숨기지 않는다. `skipped`는 범위 밖이라 가져오지
    않은 정책 수(마감 지남·수도권 밖 등)이고, `gone_kept`는 한 번에 너무 많이 사라져 숨기지 않고
    둔 정책 수다(온통청년 목록이 덜 왔을 수 있다).
    """

    run_id: str
    fetched: int
    total: int
    complete: bool
    stopped: str | None
    new: int
    updated: int
    unchanged: int
    expired: int
    hidden: int
    skipped: int
    gone_kept: int
```
