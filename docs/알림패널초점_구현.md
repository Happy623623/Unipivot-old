# 알림 패널 초점 구현 (F-35, `feat/F-35-panel-focus`)

> 📝 기준: PRD v0.9 F-35 · docs/창초점_구현.md(`useDialogFocus`) · 이 문서의 9장(구현 기록 반영)
> 적용할 곳: `main`(67af425, #80 다른 탭 로그아웃) 위. 그 트리에서 만들고 시험했다.

헤더 종 버튼이 여는 알림 패널(`NotificationPanel`, 오른쪽에서 나오는 판)은 열어도 초점이 종에 남고 Esc도 먹지 않았다. Tab을 누르면 덮개에 가려진 뒤 화면으로 초점이 갔다(창초점 PR이 남긴 일). 이제 창(`Modal`)과 같은 훅(`lib/useDialogFocus.ts`)을 쓴다. 열면 초점이 패널로 가서 제목 "알림"을 읽고, Tab은 패널 안에서 돌며, Esc·닫기·덮개로 닫으면 종으로 돌아온다. 사용자가 고른 작업이고, 방식은 사용자가 권장안("창과 같게")을 골랐다.

## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 창과 같게(모달) (사용자 선택, 권장) | 패널은 뒤 화면을 어두운 덮개로 가리고, 덮개를 누르면 닫힌다. 보기에는 이미 모달이라, 초점도 창과 같게 둔다. `role="dialog"`·`aria-modal`·`aria-labelledby`(제목 "알림"), `tabIndex=-1`. 버린 것: 비모달(Tab이 가려진 뒤 화면으로 나간다) |
| 훅은 그대로 쓴다 | `useDialogFocus`를 고치지 않고 부른다(머리 주석만 "창과 헤더 알림 패널"). 열면 패널 자체로(창과 같다 — 제목을 읽고, "모두 읽음"에 바로 가지 않게), Esc 예외(한글 조합 중·`defaultPrevented`·select)도 같다 |
| 닫혀도 패널은 그려 둔다 | 미끄러져 들어오는 움직임 때문이다. 닫힌 동안은 `inert`로 Tab 순서와 화면 읽기에서 뺀다. 원래 같이 있던 `aria-hidden`은 뺐다. 닫는 순간 초점이 남은 채로 숨겨져 브라우저가 경고하고, `inert`만으로 빠진다(검토) |
| 돌아갈 곳으로 종 ref를 넘긴다(`returnFocusRef`) | Safari·macOS Firefox는 버튼을 마우스로 눌러도 초점을 주지 않아서, 연 버튼을 몰라 닫아도 돌아가지 못한다(검토). `Header`가 종 ref를 넘긴다 |
| "다시 시도"를 누르면 먼저 패널로 초점 | 누르면 오류 블록이 사라져 초점이 `<body>`로 빠지고, 그 사이 Esc가 먹지 않았다(훅은 패널에서 키를 듣는다, 검토). 다시 받기 전에 패널로 옮긴다 |
| 알림 줄·"모든 알림 확인하기" | 지금처럼 닫고 그 화면으로 간다. 닫힐 때 종으로 돌아갔다가 화면이 바뀌면 그 종이 사라져 `<body>`가 된다. 바꾸기 전과 같다(화면 전환 뒤 초점은 따로) |
| 새 API·문서 없음 | PRD·명세는 키보드 초점을 다루지 않는다. 창초점 구현 기록의 "남은 것" 한 줄만 고친다(9장) |

## 3. 합친 뒤 확인

키보드로 본다(마우스를 쓰지 않는다).

````text
1. 아무 화면(예: /planner)에서 Tab으로 오른쪽 위 종 버튼까지 가서 Enter → 패널이 나오고 초점이 패널에 간다
   (화면 읽기 프로그램을 켰다면 "알림, 대화 상자").
2. Tab을 여러 번 → 모두 읽음 → × → 알림 줄들 → 모든 알림 확인하기 → 다시 모두 읽음으로 돈다. 뒤 화면으로 나가지 않는다.
   Shift+Tab은 거꾸로 돈다.
3. Esc → 패널이 닫히고 초점이 종 버튼에 있다(Enter를 다시 누르면 또 열린다).
4. 패널을 열고 × 를 Enter로 눌러도, 마우스로 왼쪽 어두운 곳을 눌러 닫아도 종으로 돌아온다.
5. (Safari가 있으면) 마우스로 종을 눌러 열고 Esc → 종에 초점 테두리가 보인다.
````

## 5. 확인한 것

## 6. 되돌림 시험

코드를 하나씩 망가뜨려 빌드하고 위 점검을 돌렸다. N8은 실제 모드에서만 하는 점검이라(목 모드에서는 목록 받기 실패를 만들 수 없다) 실제 모드로 빌드했고, 나머지는 목 모드다.

| 돌연변이 | 잡은 점검 |
| --- | --- |
| N1 초점 훅을 안 부름 | open: focus on panel itself (dialog named 알림); Tab x45 stays inside the panel; Shift+Tab from panel -> last control; Esc closes, focus back on bell; closed panel not exposed as dialog; bell aria-expanded=false; close button -> focus back on bell; cover click -> focus back on bell; opened without focusing the bell -> Esc returns to bell; reopen on /notifications: focus on panel |
| N2 `tabIndex=-1` 뺌 | open: focus on panel itself (dialog named 알림); Shift+Tab from panel -> last control; Tab from last -> first control; opened without focusing the bell -> Esc returns to bell; reopen on /notifications: focus on panel |
| N3 `aria-labelledby` 뺌 | open: focus on panel itself (dialog named 알림); Esc during composition ignored |
| N4 `role="dialog"` 뺌 | open: focus on panel itself (dialog named 알림); Esc during composition ignored |
| N5 `inert` 뺌 | closed panel is not in Tab order; closed panel not exposed as dialog; cover click closes; open a row: panel closes, focus not in hidden panel; panel closed on /notifications |
| N6 `ref`를 안 붙임 | open: focus on panel itself (dialog named 알림); Tab x45 stays inside the panel; Shift+Tab from panel -> last control; Esc closes, focus back on bell; closed panel not exposed as dialog; bell aria-expanded=false; close button -> focus back on bell; cover click -> focus back on bell; opened without focusing the bell -> Esc returns to bell; reopen on /notifications: focus on panel |
| N7 종 ref를 안 넘김(`returnFocusRef`) | opened without focusing the bell -> Esc returns to bell |
| N8 "다시 시도"가 패널로 초점을 안 옮김 | 다시 시도: focus moves to the panel; 다시 시도 then Esc closes |

## 7. 검토에서 고친 것

새 에이전트가 읽기만 하고 검토했다. 막을 문제는 없다고 봤고, 낮은 것 다섯 개를 짚었다.

| 지적 | 처리 |
| --- | --- |
| (낮음~중간) "다시 시도"를 누르면 오류 블록이 사라져 초점이 `<body>`로 빠지고 그동안 Esc가 안 먹는다 | 다시 받기 전에 패널로 초점을 옮긴다(되돌림 N8) |
| (낮음) `aria-hidden`을 닫는 순간 초점이 든 패널에 걸어 Chrome이 경고할 수 있다. `inert`와 겹친다 | `aria-hidden`을 뺐다. 닫힌 패널이 접근성 트리에 없는 것은 CDP로 확인했다(되돌림 N5) |
| (낮음) Safari·macOS Firefox는 클릭한 버튼에 초점을 안 줘서 닫아도 종으로 못 돌아간다(Modal도 같다) | 종 ref를 `returnFocusRef`로 넘긴다(되돌림 N7). `Modal`을 여는 곳들은 그대로다(8장) |
| (낮음) 알림 줄·"모든 알림 확인하기"로 화면이 바뀌면 초점이 `<body>` | 그대로 둔다. 바꾸기 전과 같고, 화면 전환 뒤 초점은 이 PR 밖이다 |
| (낮음) 창초점 구현 기록의 "알림 패널은 따로 본다"가 낡는다 | 그 줄을 고친다(9장) |

검토가 문제없다고 본 것은 다음과 같다.
- **여닫는 순서**: 열 때는 `inert`가 먼저 풀린 뒤 초점이 간다. 미끄러지는 중(`translate-x-full`)에도 초점·Tab이 정상이다. 닫을 때는 `inert` 때문에 초점이 이미 빠졌어도, 아직 패널 안에 있어도 종으로 간다.
- **Modal과 겹침**: Modal(z 80)이 열린 동안에는 종을 누를 수 없어 같이 열리지 않는다.
- **그 밖**: StrictMode, 패널 안 `role="status"` 읽기, 300줄 규칙도 문제없다. `#notification-panel`은 종의 `aria-controls`만 쓰고, 예전 이름 "알림 패널"을 찾는 곳도 없다.

## 8. 남은 것

- 창(`Modal`)을 여는 곳들도 Safari에서 마우스로 열면 닫은 뒤 연 버튼으로 못 돌아간다 — 필요하면 여는 쪽마다 `returnFocusRef` → 10/21 `useDialogFocus`가 1초 안에 누른 버튼을 연 버튼으로 본다(docs/화면전환초점_구현.md).
- 알림 줄·"모든 알림 확인하기"로 화면이 바뀐 뒤 초점(지금은 `<body>`), 알림 패널에서 바로 연 정보 입력 창의 초점 복귀(창초점 8장) → 10/21 새 화면 제목으로 옮기고(docs/화면전환초점_구현.md), 정보 입력 창은 "AI 자격 판정" 제목으로 돌아간다(docs/접근성꼬리_구현.md).
- 창 진행 중 닫기(저장·탈퇴 중 Esc), 창 `aria-describedby`, `/notifications` 화면과 헤더 패널의 목록 동기화(인수인계 7장) → 10/20 #82, 10/21 docs/접근성꼬리_구현.md·docs/알림동기화_구현.md.
