# 시나리오 녹화 저장소 — 받기 주소(`signed_url`)를 준다(F-44 후속, 시나리오 실행)

> 📝 기준: API 명세 v0.4 6장 `GET /files/{file_id}/url` · 12장 시나리오 실행(`fixtures: "recorded"`) · 2026-10-20
>
> 적용할 곳: **탈퇴 저장소 가드 PR(#69)까지 합친 main** 위 새 브랜치. 앞의 문서함 받기 PR(web)과는 겹치는 파일이 없다.
> **마이그레이션 없음** · 명세·PRD·ERD 안 바뀜

시나리오 실행(명세 12장)은 바깥 서비스 대신 녹화한 것을 쓴다. 파일 저장소는 `app/eval/fakes.py`의 `RecordedStorage`인데,
문서함(#68)이 더한 `signed_url()`이 거기엔 없었다. 그래서 시나리오가 `GET /files/{id}/url`을 부르면 부모 클래스가
`recorded://storage`로 실제 요청을 보내다 502가 난다. 이 PR은 녹화 저장소에도 받기 주소를 넣는다 — 실제처럼 서명 경로
모양이고, 없는 파일은 서명할 때 `StorageMissing`이다(문서함 받기가 404를 내는 길). 시나리오에 F-44가 아직 없어서 지금
쓰는 곳은 없다. 시나리오에 문서함을 넣을 때를 위한 준비다.

## 정한 것

1. **주소 모양은 실제와 같다.** `recorded://storage/object/sign/uploads/<경로>?token=<새 값>&download=<이름>`. 경로는 `/`만
   남기고 가리고, 이름은 다 가린다(실제 `signed_url()`과 같은 `quote`). 부를 때마다 토큰이 다르다.
2. **없는 파일은 서명할 때 `StorageMissing`이다.** 실제 Supabase가 그렇다(10/19). 문서함 받기는 이걸 받아 404로 바꾼다.
3. **부른 기록을 남긴다**(`storage.signed`: 경로·받을 이름·수명). 시나리오 시험이 "무엇을 받게 했는지"를 볼 수 있다.
4. 주소는 열리지 않는다(`recorded://`). 시나리오는 주소 모양과 만료 시각만 보면 된다.

## 검토에서 고친 것

독립 검토(새 에이전트, 읽기만. C·D·E 세 변경을 한 번에 봤다)에서 꼭 고칠 것은 없었다. 시그니처·타입이 부모 클래스와 같고,
경로·이름 가림이 실제 `signed_url()`과 같고, `StorageMissing` 문구도 `_send`의 모양과 같다고 확인했다.

| 본 것 | 고친 것 |
| --- | --- |
| docstring의 "(문서함 받기가 404를 낸다)"가 시나리오 세계에서는 거짓이다 — 시나리오 설정(`eval_settings`)은 저장소 설정이 비어 있어 `storage_settings_problem()`이 고칠 점을 내고, 받기 주소는 `StorageMissing`을 받아도 502를 낸다 | docstring을 고쳤다("설정이 맞으면 404, 시나리오 설정은 비어 있어 502"). 시나리오 설정에 모양만 맞는 더미 키·주소를 넣는 안은 안 골랐다 — 쓰는 곳이 없는데 설정을 늘리지 않는다 |
| 서명 주소는 열쇠(명세 6장)라 시나리오 `check`에 넣으면 `tool_calls.output`에 남는다 | docstring에 "주소 자체는 check에 넣지 말고 모양만 볼 것"을 적었다 |
| 되돌림 시험 R3(토큰 고정)이 처음에 살아남았다 — 두 번째 주소가 이름이 달라서 어차피 달랐다 | 같은 파일·같은 이름으로 한 번 더 받아 다르다고 본다 |

그대로 둔 것: 옛 구현 기록(`문서함_구현.md`·`탈퇴저장소가드_구현.md`의 "녹화 저장소에는 받기 주소가 없다")은 그때 기록이라 손대지 않았다(관례).
