# 계획서 일정의 캘린더 표시 — "캘린더에 넣기"가 그대로 보이던 것

> 📝 기준: API 명세 v0.4 9장 · 2026-10-18
>
> 적용할 곳: **F-53 2부까지 합친 main** 위 새 브랜치. **마이그레이션 없음**

네가 브라우저에서 본 것 — 계획서 일정을 캘린더에 넣고 과목을 다시 열면 **"캘린더에 넣기"가 또
보이던 문제**다. 서버가 "이 일정이 캘린더에 들어갔는지"를 안 알려 줘서, 화면이 그 화면에서 방금 넣은
것만 기억하고 있었다(새로고침하면 잊는다).

과목 상세의 계획서 일정에 `calendar_registered`를 더했다. 이름과 기준은 **과제 목록·공고 상세와 같다**
(`external_event_id`가 있는 행만 true).

| 값 | 결과 |
| --- | --- |
| 시나리오 | **18/18 통과**(S15에 확인 1개 추가) · 확인 244개 |
| 테스트 | **1328 passed**(2부 1327 → +1 DB 테스트) · DB 없이 1005 passed, 323 skipped |
| web | typecheck·build 통과, **브라우저로 눈으로 확인**(아래) |
| 되돌림 시험 | 돌연변이 3개 전부 잡힘 |
| 마이그레이션 | 없음 |

## 정한 것

1. **이름은 `calendar_registered`로 맞췄다.** 과제 목록(`GET /lms/assignments`)과 공고 상세가 이미 그
   이름·그 기준(실제로 등록된 행)을 쓴다. `in_calendar` 같은 새 이름을 만들면 화면 쪽에서 둘을 같은
   뜻으로 다루기 어려워진다.
2. **자리만 잡고 넣다 만 일정은 false다.** Google이 막혀 `external_event_id`가 비어 있는 행은 아직
   들어간 것이 아니라서, 화면이 다시 넣을 수 있어야 한다.
3. **추출 결과에서는 늘 false다.** `SyllabusItemView`는 확인 화면(추출 직후)과 과목 상세가 함께 쓰는
   모양이다. 확정하기 전에는 캘린더에 넣지 않으니 기본값 false로 두고, 과목 상세만 실제 값을 채운다.
4. **화면은 둘을 합쳐 본다.** 방금 넣은 것(`added`)과 서버가 준 `calendar_registered` 중 하나라도
   참이면 "캘린더에 넣었어요"다. 방금 넣은 것을 지우지 않은 이유는, 그 응답이 돌아온 직후 과목 상세를
   다시 받지 않기 때문이다(한 번 더 부르면 화면이 깜빡인다).
5. **목데이터도 같이 맞췄다.** 목 모드의 과목 상세는 "중간고사는 들어갔고 Homework 4는 아직"으로 두고,
   목 저장소는 캘린더에 넣은 일정을 기억해 다시 열어도 그대로 보이게 했다 — 목으로 보는 화면과 실제
   화면이 달라지면 둘 중 하나가 틀린 것을 못 본다.
