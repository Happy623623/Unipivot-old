> 📝 기준: API 명세 v0.4 4장 `DELETE /me`·6장 `GET /files/{file_id}/url`(저장소 설정에 고칠 점이 있으면 502) · 2026-10-20
>
> 적용할 곳: **탈퇴 저장소 가드 PR(#69)까지 합친 main** 위 새 브랜치. #69와 같은 파일(`storage.py`·탈퇴 시험)을 고쳐서 #69가
> 들어간 main이어야 패치가 맞는다. **마이그레이션 없음** · 명세·PRD·ERD 안 바뀜 · `api/.env.example` 설명 2줄

`storage_settings_problem()`은 키 모양만 봤다. 그래서 `SUPABASE_URL`에 경로가 붙어 있으면(`…supabase.co/rest/v1`) 저장소가

## 정한 것

1. **`SUPABASE_URL`은 프로젝트 주소(`https://<ref>.supabase.co`)만 된다.** http(s)로 시작하고, 계정 정보(`@`)·예시 값(`<…>`)이
   없고, **경로·쿼리·조각이 없어야** 한다(끝의 `/` 하나는 괜찮다). 저장소 경로 `/storage/v1`은 서버가 붙인다. 대문자 스킴, 포트,
   자체 도메인, 로컬 Supabase CLI(`http://127.0.0.1:54321`), IPv6는 통과한다.
2. **`SUPABASE_STORAGE_BASE`를 따로 넣었으면 그것을 보고 `SUPABASE_URL`은 보지 않는다.** 시험·개발용 가짜 저장소와, 경로가 꼭
   필요한 자체 호스팅의 탈출구다. 이 값은 경로가 있을 수 있어 경로는 보지 않는다(http(s)·`@`·예시 값만). 빈칸뿐이면 없는
   것으로 보고 `SUPABASE_URL`을 본다(아래 남은 것).
3. **값은 보여 주지 않는다.** DB 주소를 잘못 넣으면 비밀번호가 들어 있다. 문구는 어떤 변수를 어떻게 고칠지만 말한다
   ("SUPABASE_URL 값에 경로가 붙어 있어요(…/rest/v1 같은 것) … 경로가 꼭 필요한 자체 호스팅이면 SUPABASE_STORAGE_BASE에").
4. 검사 순서는 **비었는지 → 주소 → 버킷 → 키**다. 켤 때 경고(`app/main.py`), 탈퇴 가드(`app/account.py`), 받기 주소의 "없는
   파일" 판정(`app/routers/files.py`)이 같은 함수를 쓰므로 셋 다 바뀐다: 경로가 붙은 `SUPABASE_URL`이면 파일이 있는 탈퇴는
   저장소를 부르기 전에 502, 받기는 `NoSuchKey`를 믿지 않고 502다.
5. `auth_settings_problem`(로그인 설정)과 `@`·스킴·예시 값 검사가 겹치지만 합치지 않았다(로그인 쪽은 경로 검사가 없고, 범위 밖).

## 검토에서 고친 것

독립 검토(새 에이전트, 읽기만. C·D·E를 한 번에 봤다)에서 꼭 고칠 것은 없었다. 끝 `/`·대문자 스킴·포트·IPv6·자체 도메인·로컬 http가
모두 통과하고, `urlsplit`은 `ValueError`만 내며(잡는다), 어떤 문구에도 주소 값·자격이 들어가지 않고, 문구가 해요체에 할 일을
담는다고 확인했다. 아래를 고친 뒤 시험·되돌림 시험을 다시 돌렸다.

| 본 것 | 고친 것 |
| --- | --- |
| 주소 값이 새지 않는지 보는 검사가 헛돌았다 — 시험 주소는 `abcdefghijklmnopqrst.supabase.co`인데 `"ref.supabase.co" not in found`를 봐서 호스트가 통째로 새도 못 잡고, 안내 문구의 `<ref>` 덕에만 통과했다 | 모든 경우에 `"abcdefghijklmnopqrst" not in found`로 본다 |
| 빈칸뿐인 `SUPABASE_STORAGE_BASE`("  ")면 이름은 `SUPABASE_URL`을 가리키는데 값은 빈칸을 봐서 엉뚱한 변수를 지목했다 | `strip()`한 값 하나로 이름·값을 같이 정한다 + 시험 |
| 조사가 안 맞았다("SUPABASE_STORAGE_BASE이") | "{이름} 값이/값에"로 중립형 |
| 자체 호스팅처럼 `SUPABASE_URL`에 경로가 정당한 경우가 이제 막히는데 탈출구(`SUPABASE_STORAGE_BASE`)를 문구·`.env.example`이 말해 주지 않았다 | 경로 문구 끝과 `.env.example`에 "경로가 꼭 필요하면 SUPABASE_STORAGE_BASE에 저장소 주소를 따로" |

## 남은 것

- `Settings.storage_base_url`은 빈칸뿐인 `SUPABASE_STORAGE_BASE`를 "있음"으로 본다(`storage_base_url`이 `""`가 아니라
  빈칸을 돌려준다 → `_send`가 주소 없이 간다). 검사는 빈칸을 없는 것으로 보고 `SUPABASE_URL`을 봐서 경고는 맞게 뜨지만,
  설정 자체는 그대로다. 빈칸을 넣을 일이 없어 두었다.
- 로그인 설정 검사(`auth_settings_problem`)에는 경로 검사가 없다. 경로가 붙은 `SUPABASE_URL`이면 JWKS 주소도 틀려 503이
  나는데 원인 안내는 저장소 경고에만 있다.
- 앞 PR의 남은 것은 그대로다.
