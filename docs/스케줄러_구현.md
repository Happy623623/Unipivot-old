# 서버 안 스케줄러 — 알림이 저절로 나가게

> 📝 기준: PRD v0.9 9장(스케줄러) · API 명세 v0.4 12장 · 2026-10-18
>
> 적용할 곳: **웹 푸시 2부까지 합친 main** 위 새 브랜치. **마이그레이션 없음**

지금까지 정기 작업(`/internal/jobs/*`)을 **깨우는 게 아무것도 없었다**. PRD 9장에 "FastAPI 내
스케줄러 또는 Supabase 크론 — W1 결정"으로 남아 있던 칸이다. 그래서 알림은 사람이 curl을 쳐야
나갔다. 서버 안에서 도는 쪽으로 정하고 만들었다.

| 값 | 결과 |
| --- | --- |
| 테스트 | **1381 passed**(1359 → +22) · DB 없이 1044 passed, 337 skipped |
| 시나리오 | **18/18 통과** · 비용 0.011040 USD · LLM 8회 — 1차 베이스라인과 한 자리도 다르지 않다 |
| 실제 실행 | 서버를 켜서 **스케줄러가 뜨고 발송이 돌고 깨끗이 꺼지는 것**까지 로그로 확인 |
| 되돌림 시험 | 돌연변이 **21개 전부 잡힘** — 다섯은 시험 셋을 더하고 코드 둘을 고친 뒤다(아래) |
| 마이그레이션 | 없음 |
| 새 파일 | 4개(작업 알맹이·스케줄러·시험 둘) · 고친 파일 11개 |

## 정한 것

1. **FastAPI 안에서 돈다.** 바깥 크론(GitHub Actions·Supabase pg_cron)은 **공개 주소가 있어야**
   해서 배포가 먼저다. 서버 안 스케줄러는 지금 로컬에서도 쓸모가 있고, 배포해도 그대로 돈다.
   배포한 뒤에 바깥 크론이 낫다고 판단하면 `SCHEDULER_ENABLED=false`로 끄고 주소를 부르면 된다 —
   **둘은 같은 함수를 부른다.**
2. **작업 알맹이를 `app/jobs.py`로 뺐다.** 라우터와 스케줄러가 같은 함수를 부른다. 한쪽만 고쳐서
   "손으로 부를 때와 저절로 돌 때가 다른" 일을 막는다. 라우터는 이제 세 줄짜리 껍데기다.
3. **기본값은 꺼짐(`SCHEDULER_ENABLED=false`)이다.** 켜는 것은 `.env` 한 줄이다. 시험·시나리오가
   도는 동안 배치가 끼어들면 안 되고, 바깥 크론을 쓰는 배포에서 둘이 같이 돌면 안 된다.
4. **예약은 KST 08:30이다.** 공고 알림 시각이 09:00이고 지난 시각은 만들지 않으니(PRD F-33),
   그 전에 돌아야 그날 알림이 생긴다. 시험이 이 둘의 관계를 못 박는다(`SCHEDULE_AT < NOTIFY_HOUR`).
5. **발송만 서버를 켤 때 바로 돈다.** 꺼져 있던 동안 밀린 알림을 바로 보내려는 것이다. LMS 동기화와
   예약은 첫 주기를 기다린다 — `--reload`로 서버가 자주 다시 뜨는 개발 중에 **모델을 부르는 일**과
   사용자 전체를 훑는 일이 매번 돌면 곤란하다.
6. **한 작업은 한 줄로 돈다**(돌고 → 자고 → 돌고). 주기보다 오래 걸려도 겹치지 않는다. 작업마다
   asyncio 줄 하나라 LMS 동기화가 느려도 알림 발송은 제때 돈다.
7. **일이 터져도 로그만 남기고 다음 차례에 다시 돈다.** 한 번 실패로 스케줄러가 죽으면 그 뒤로
   아무 알림도 안 나간다 — 조용히 멈추는 것이 가장 나쁘다.
8. **끌 때는 시간을 끊는다**(5초). 이 레포의 `TaskRunner.drain(timeout=10)`과 같은 방식이다.
   멈추지 않는 줄이 있어도 서버를 끄는 길이 막히지 않는다.
9. **앱 로그가 보이게 한 줄 깔았다.** uvicorn은 자기 로거만 꾸며서, 그대로 두면 "정기 작업 끝"
   같은 info 로그가 **아무 데도 안 남는다**. 도는지 끄는지 알 수 없는 배치는 없는 것과 같다.
   대신 평가 CLI에서는 바깥 호출 로그 한 줄씩을 끈다(결과 표만 보이게).
10. **의존을 만드는 함수와 FastAPI 의존을 나눴다**(`push_sender_for`·`llm_for`·
    `lms_sync_service_for`). 요청 밖에서도 같은 것을 만들어야 하는데, 지금까지는 `Request`가
    있어야만 만들 수 있었다. `Depends(...)` 쪽은 그 함수를 부르는 껍데기로 남겼다.
11. **워커는 하나로 둔다.** 여러 프로세스로 띄우면 같은 일이 여러 번 돈다. 배포 때 지킬 일이라
    `.env.example`과 명세 12장에 적어 뒀다.

## 구조

```
app/jobs.py          작업 알맹이 셋(동기화·예약·발송). FastAPI를 모른다
app/scheduler.py     Job(이름·주기·시작 때 도는가) + Scheduler(작업마다 asyncio 줄 하나)
app/routers/internal.py  /internal/jobs/* — 이제 jobs.py를 부르는 껍데기
app/main.py          lifespan에서 켜고 끈다(+ 앱 로그 깔기, try/finally)
```

손으로 부르는 길과 저절로 도는 길이 **같은 함수**에서 만난다:

```
POST /internal/jobs/send-notifications ─┐
                                        ├─ app/jobs.py: send_notifications()
Scheduler(5분) ─ app_jobs().send ───────┘
```

## 남은 것

- **배포.** 이 스케줄러는 서버가 떠 있어야 돈다. 무료 플랜처럼 서버가 자는 곳에 올리면 자는 동안
  안 돈다 — 그때는 바깥 크론으로 깨우는 쪽이 맞다. 배포를 하면서 다시 고르자.
- **명세 12장의 다른 작업들**(`crawl-notices`·`fetch-policies`·`crawl-contests`·
  `expire-opportunities`)은 아직 엔드포인트가 없다. 생기면 `app_jobs`에 한 줄씩 더하면 된다.
- **청년정책 정기 수집**은 지금도 사람이 CLI로 돌린다(PRD 체크리스트 그대로).
- **워커 하나 제한**을 코드가 막지는 못한다. 여러 개로 띄우면 같은 일이 여러 번 돈다 — 배포 설정에서
  지킬 일이라 문서에만 적었다. DB 잠금으로 막는 방법은 배포 모양이 정해진 뒤에 보자.
- **예약 작업이 하루 한 번만 돈다.** 서버가 08:30에 꺼져 있었으면 그날은 건너뛴다(다음 날 돈다).
  놓친 하루를 따라잡는 장치는 넣지 않았다 — 마감 임박 알림은 D-3·D-1 두 번이라 하루를 놓쳐도
  한 번은 간다.

````text
### 서버 안 스케줄러

`SCHEDULER_ENABLED=true`면 서버가 세 작업을 직접 돈다(PRD 9장). 위 표의 작업을 **같은 함수**로 부르므로
손으로 부를 때와 결과가 같다.

| 작업 | 주기 | 서버를 켤 때 |
| --- | --- | --- |
| 알림 발송 | 5분 | 바로 한 번 돈다(꺼져 있던 동안 밀린 알림을 보낸다) |
| LMS 동기화 | 30분 | 안 돈다 |
| 공고 알림 예약 | 하루 한 번 KST 08:30 | 안 돈다 |

- 예약이 **KST 08:30**인 것은 알림 시각이 09:00이고 지난 시각은 만들지 않기 때문이다(PRD F-33)
- 작업 하나가 실패해도 로그만 남기고 다음 차례에 다시 돈다. 주기보다 오래 걸려도 겹쳐 돌지 않는다
- **바깥 크론과 같이 켜지 않는다.** 바깥에서 부르려면 이 값을 꺼 둔다
- **워커는 하나여야 한다.** 여러 프로세스로 띄우면 같은 일이 여러 번 돈다
````

#### `api/app/jobs.py`

```python
"""정기 작업의 알맹이 (API 명세 12장). 두 곳에서 부른다.

- `POST /internal/jobs/*` — 사람이나 바깥 크론이 부를 때(`app/routers/internal.py`)
- 서버 안 스케줄러 — 켜 두면 알아서 도는 쪽(`app/scheduler.py`)

둘이 같은 함수를 부르게 둔 까닭은, 한쪽만 고쳐서 "손으로 부를 때와 저절로 돌 때가 다른" 일을
막으려는 것이다. 여기 함수들은 FastAPI를 모른다 — 다 만들어진 저장소·서비스와 `now`만 받는다.
"""

from datetime import datetime

from app.lms.sync import LmsSyncService
from app.push.send import PushSender
from app.repositories.notifications import NotificationRepository
from app.repositories.push import PushRepository
from app.schemas.lms import SyncJobResult
from app.schemas.notifications import ScheduleResult, SendResult


async def lms_sync(service: LmsSyncService, *, now: datetime) -> SyncJobResult:
    """연결된 사용자의 과목·과제를 동기화한다 (F-51).

    한 사람이 실패해도 다음 사람을 계속한다(실패는 그 사람의 실행 기록에 남는다). 토큰이 막힌
    사람은 연결을 `error`로 바꿔 화면이 다시 연결을 안내한다. 최근에 동기화한 사람은 건너뛴다.
    """
    outcome = await service.sync_all(now=now)
    return SyncJobResult(
        users=outcome.users,
        synced=outcome.synced,
        failed=outcome.failed,
        skipped=outcome.skipped,
        new_assignments=outcome.new_assignments,
        due_changed=outcome.due_changed,
        submitted=outcome.submitted,
    )


async def schedule_notifications(repo: NotificationRepository, *, now: datetime) -> ScheduleResult:
    """공고 알림(새 적격·마감 임박·정보 필요)을 예약한다.

    같은 알림은 한 번만 만들고(사용자당 `dedupe_key` 1행), 마감이 바뀌면 아직 보내지 않은 행의
    시각만 고친다. 보낼 이유가 없어진 행은 지운다(저장소 머리말).
    """
    return await repo.schedule(now=now)


async def send_notifications(
    repo: NotificationRepository,
    push_repo: PushRepository,
    sender: PushSender,
    *,
    now: datetime,
) -> SendResult:
    """보낼 때가 된 알림을 보낸다.

    숨긴 공고의 알림과 하루 한도를 넘는 알림은 보내지 않고 둔다. 푸시 구독이 없거나 푸시를 끈
    사용자는 푸시만 건너뛰고 알림함에는 남는다(F-35).

    푸시는 **알림함 행을 닫은 뒤에** 보낸다(F-33). 푸시가 실패해도 알림은 보낸 것으로 남는다 —
    같은 알림을 두 번 보내지 않는 쪽을 택했다(명세 10장). 사라진 구독(404·410)은 지운다.
    """
    sent = await repo.send(now=now)
    pushed = await sender.send(await push_repo.targets(sent.ids))
    dropped = await push_repo.drop_endpoints(pushed.gone)
    return SendResult(
        **{
            **sent.result.model_dump(),
            "pushed": pushed.sent,
            "push_failed": pushed.failed,
            "push_dropped": dropped,
        }
    )
```

#### `api/app/scheduler.py`

```python
"""서버 안 스케줄러 (PRD 9장 "스케줄러"). 켜 두면 정기 작업이 알아서 돈다.

`POST /internal/jobs/*`를 사람이 부를 때와 **같은 함수**(`app/jobs.py`)를 부른다. 바깥 크론
(GitHub Actions·pg_cron)을 쓰려면 이것을 끄고 그 주소를 부르면 된다 — 둘을 같이 켜지 않는다.

도는 것:

| 작업 | 주기 | 서버를 켤 때 |
| --- | --- | --- |
| 알림 발송 | 5분 | **바로 한 번** 돈다(서버가 꺼져 있던 동안 밀린 알림을 바로 보낸다) |
| LMS 동기화 | 30분 | 안 돈다(첫 30분은 기다린다) |
| 공고 알림 예약 | 하루 한 번 KST 08:30 | 안 돈다 |

지키는 것:
- **일 하나가 터져도 로그만 남기고 다음 차례에 다시 돈다.** 한 번 실패로 스케줄러가 죽지 않는다
- 일이 주기보다 오래 걸려도 **겹쳐 돌지 않는다**(한 작업은 한 줄로 돈다: 돌고 → 자고 → 돌고)
- 예약은 **KST 08:30**이다. 공고 알림 시각이 KST 09:00이고 지난 시각은 만들지 않아서,
  그 전에 돌아야 그날 알림이 생긴다(PRD F-33)
- 서버를 끌 때 돌던 일은 취소한다. 작업은 모두 다시 돌려도 되는 것들이다
- **워커는 하나여야 한다.** 여러 프로세스로 띄우면 같은 일이 여러 번 돈다
"""

import asyncio
import logging
from collections.abc import Awaitable, Callable
from dataclasses import dataclass
from datetime import datetime, time, timedelta
from typing import Any

from app.clock import current_time
from app.eligibility import KST
from app.jobs import lms_sync, schedule_notifications, send_notifications
from app.llm.deps import llm_for
from app.lms.sync import lms_sync_service_for
from app.push.deps import push_sender_for
from app.repositories.notifications import NotificationRepository
from app.repositories.push import PushRepository

logger = logging.getLogger(__name__)

SEND_EVERY = timedelta(minutes=5)
LMS_EVERY = timedelta(minutes=30)
SCHEDULE_AT = time(8, 30)  # KST. 알림 시각(09:00)보다 앞이어야 한다


@dataclass(frozen=True)
class Job:
    """도는 일 하나. `every`(간격)나 `daily_at`(KST 하루 한 번) 중 하나를 준다."""

    name: str
    run: Callable[[], Awaitable[Any]]
    every: timedelta | None = None
    daily_at: time | None = None
    at_start: bool = False  # 서버를 켜자마자 한 번 도는가


def seconds_until(now: datetime, at: time) -> float:
    """KST로 다음 `at`까지 남은 초. 지금이 딱 그 시각이면 내일까지 기다린다(두 번 돌지 않는다)."""
    here = now.astimezone(KST)
    target = here.replace(hour=at.hour, minute=at.minute, second=0, microsecond=0)
    if target <= here:
        target += timedelta(days=1)
    return (target - here).total_seconds()


class Scheduler:
    """작업마다 asyncio 줄 하나. 시험에서 `sleep`·`now`를 바꿔 시간 없이 돌린다."""

    def __init__(
        self,
        jobs: list[Job],
        *,
        sleep: Callable[[float], Awaitable[None]] = asyncio.sleep,
        now: Callable[[], datetime] = current_time,
    ) -> None:
        self._jobs = jobs
        self._sleep = sleep
        self._now = now
        self._tasks: list[asyncio.Task[None]] = []

    def start(self) -> None:
        for job in self._jobs:
            self._tasks.append(asyncio.create_task(self._loop(job), name=f"scheduler:{job.name}"))
        logger.info("스케줄러를 켰어요: %s", ", ".join(job.name for job in self._jobs))

    async def stop(self, timeout: float = 5.0) -> None:
        """작업을 취소하고 멈출 때까지 기다린다(TaskRunner.drain과 같이 시간을 끊는다).

        제때 멈추지 않은 줄은 그대로 들고 있는다 — 서버를 끄는 길이 여기서 영영 막히면 안 된다.
        """
        for task in self._tasks:
            task.cancel()
        if self._tasks:
            _, pending = await asyncio.wait(set(self._tasks), timeout=timeout)
            if pending:
                logger.warning("정기 작업 %d개가 제때 멈추지 않았어요", len(pending))
            self._tasks = list(pending)

    @property
    def running(self) -> int:
        return len([task for task in self._tasks if not task.done()])

    async def _loop(self, job: Job) -> None:
        if not job.at_start:
            await self._sleep(self._wait_for(job))
        while True:
            await self._run_once(job)
            await self._sleep(self._wait_for(job))

    def _wait_for(self, job: Job) -> float:
        if job.daily_at is not None:
            return seconds_until(self._now(), job.daily_at)
        assert job.every is not None, f"{job.name}에 주기가 없어요"
        return job.every.total_seconds()

    async def _run_once(self, job: Job) -> None:
        started = self._now()
        try:
            result = await job.run()
        except Exception:  # 취소(CancelledError)는 Exception이 아니라 그대로 올라간다
            logger.exception("정기 작업 %s이(가) 실패했어요. 다음 차례에 다시 해요", job.name)
            return
        seconds = (self._now() - started).total_seconds()
        logger.info("정기 작업 %s 끝 (%.1f초): %s", job.name, seconds, result)


def app_jobs(app: Any, *, now: Callable[[], datetime] = current_time) -> list[Job]:
    """앱 상태에 묶인 작업 목록. 매번 새 연결로 저장소를 만든다(연결을 오래 쥐지 않는다).

    `now`를 바꿀 수 있게 둔 것은 시험 때문이다 — 지난 시각을 주면 보낼 것이 없어서 DB를 건드리지
    않고 배선만 확인할 수 있다.
    """
    state = app.state

    async def send() -> Any:
        settings = state.settings
        sender = push_sender_for(state, settings)
        async with state.pool.connection() as conn:
            return await send_notifications(
                NotificationRepository(conn), PushRepository(conn), sender, now=now()
            )

    async def schedule() -> Any:
        async with state.pool.connection() as conn:
            return await schedule_notifications(NotificationRepository(conn), now=now())

    async def sync() -> Any:
        service = lms_sync_service_for(
            state, settings=state.settings, llm=llm_for(state), runner=state.runner
        )
        return await lms_sync(service, now=now())

    return [
        Job(name="알림 발송", run=send, every=SEND_EVERY, at_start=True),
        Job(name="LMS 동기화", run=sync, every=LMS_EVERY),
        Job(name="공고 알림 예약", run=schedule, daily_at=SCHEDULE_AT),
    ]
```

```python
async def _notification_counts() -> tuple[int, int]:
    conn = await connect()
    try:
        row = await (
            await conn.execute(
                "select count(*) as all_rows,"
                " count(*) filter (where sent_at is not null) as sent_rows from notifications"
            )
        ).fetchone()
        assert row is not None
        return row["all_rows"], row["sent_rows"]
    finally:
        await conn.close()
```
