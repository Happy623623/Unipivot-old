## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| `useLateOutcome(open)`의 `report(글)`: 창이 닫혀 있을 때만 안내를 띄운다 | 창이 열려 있으면 창 안 글이 보인다 — 같은 말을 두 번 하지 않는다. 성공한 뒤 창을 스스로 닫는 곳은 닫기 **전에** 불러서 평소 성공에는 안내가 안 뜬다 |
| 닫힌 창 실패 글은 `lateFailure(오류, 무엇이 실패했는지, 다시 할 방법)` | 창 안 글("잠시 후 다시 눌러 주세요")은 닫힌 창의 버튼을 가리키고, 연결 해제 둘(LearningX·Google Calendar)은 같은 글이라 무엇이 실패했는지 모른다. 서버가 준 4xx 까닭은 그대로 쓰고, 서버에 닿지 못한 것·5xx는 다시 할 방법을 쓴다 |
| 칸 오류(422)는 "수정을 눌러 입력한 값을 확인해 주세요" | 칸 오류는 창을 다시 열면 지워진다 |
| LearningX 연결의 지난 시도는 `announce`(창이 열려 있어도 띄운다) | 15초 뒤 닫고 다시 열면 새 시도라 지난 결과를 창 안에 그리지 않는다. 안 띄우면 아무 데도 안 보인다 |
| 안내는 6초, 마우스·초점이 있는 동안은 닫지 않는다 | 그 일의 유일한 결과라 평소 안내(2.2초)보다 오래 둔다 |
| 학업 화면은 다시 받는 동안·다시 받지 못했을 때 지난 목록을 둔다(`useAsyncData`의 `keep`) | 연결하면 목록을 다시 받는데 그동안 뼈대로 바뀌어 연결 창이 내려갔다 — 늦은 안내도, 창 안 "N개 과목을 불러왔어요"도(이건 전부터) 사라졌다. 다시 받지 못하면 위에 알린다 |
| 온보딩 LearningX 단계: 창을 닫은 뒤에 연결되면 "LearningX를 연결했어요" + "시작하기" | 창이 닫혀 있어 다음으로 넘어갈 길이 없었다. 초점이 있던 "연결하기"가 사라지면 "시작하기"로 옮긴다 |

고친 창: 설정의 프로필 수정·탈퇴, 연결 서비스의 LearningX·Google Calendar 연결 해제, LearningX 연결(학업·온보딩), 공고 상세의 정보 입력(동의·저장).
안 고친 창: 소득 동의 설정(오류를 창 밖에 그린다), 플래너 하루 패널(화면이 안내로 알린다), 준비하기·신고·포스터 원문(진행 중 잠금이 없다).

## 8. 남은 것

- 안내가 여럿 겹치면(설정 화면에 다섯 자리) 같은 자리에 겹친다 — 드물다.
- `announce` 안내는 열린 창(`aria-modal`) 밖이라 일부 화면 읽기 프로그램(VoiceOver)은 안 읽을 수 있다. 화면에는 창 위에 보인다.
- 온보딩에서 "나중에"를 누른 뒤 연결이 끝나면 단계가 내려가 안내도 사라진다(연결은 됐다 — 설정에서 보인다).
- 학업 화면은 연결한 뒤 `last_synced_at`을 비운 채(아직 없음) 둔다 — 전부터. 다음에 화면을 열면 맞는다.

## 10. 코드와 패치

새 파일 하나와 패치 하나. 패치는 **main(4faad26)** 기준이다.

### 코드 (새 파일)

#### `web/src/lib/useLateOutcome.ts`

````ts
import { useCallback, useLayoutEffect, useRef } from "react";
import { ApiError } from "@/api/client";
import useToast, { type ToastHold, type ToastState } from "@/lib/useToast";

// 창 안의 일(저장·해제·탈퇴 등)이 끝났을 때 창이 그새 닫혔으면 결과를 화면 아래 안내로 띄운다.
// 진행 중인 창은 15초까지만 안 닫혀서(lib/useCloseLock.ts) 그 뒤에 닫으면, 창 안에 그리는 오류·완료 글이 보이지 않는다.
// report(글): 창이 아직 열려 있으면 아무것도 안 하고 false(창 안에 보인다), 닫혔으면 안내를 띄우고 true.
// 성공한 뒤 창을 스스로 닫는 곳은 닫기 **전에** 부른다(그래야 평소 성공에는 안내가 뜨지 않는다).
// announce(글): 창이 열려 있어도 띄운다. 창을 다시 열어 새로 시작해서 지난 결과를 창 안에 그리지 않는 곳에 쓴다.
// 안내는 부르는 쪽이 <Toast toast={…} onHold={…} />로 그린다(창은 닫혀 있어도 이 자리는 남아 있다).
// 이 안내가 그 일의 유일한 결과라 평소 안내보다 오래 두고, 마우스·초점이 있는 동안은 닫지 않는다
export default function useLateOutcome(open: boolean): {
  report: (text: string) => boolean;
  announce: (text: string) => void;
  toast: ToastState;
  hold: ToastHold;
} {
  const openRef = useRef(open);
  useLayoutEffect(() => {
    openRef.current = open;
  }, [open]);
  const [toast, show, , hold] = useToast(6000);
  const announce = useCallback((text: string) => show(text), [show]);
  const report = useCallback(
    (text: string) => {
      if (openRef.current) return false;
      show(text);
      return true;
    },
    [show],
  );
  return { report, announce, toast, hold };
}

// 닫힌 창의 실패 안내 글. 창 안 글("잠시 후 다시 눌러 주세요")은 닫힌 창의 버튼을 가리키고 무엇이 실패했는지 말하지 않아서,
// 무엇이 실패했는지(lead) 앞에 붙이고 서버가 준 까닭(4xx 문구)이 있으면 그것을, 없으면 다시 할 방법(retry)을 붙인다.
// 서버에 닿지 못한 것(NETWORK_ERROR)·5xx는 까닭 대신 다시 할 방법을 쓴다(오래 걸린 요청이 흔히 그렇게 끝난다)
export function lateFailure(caught: unknown, lead: string, retry: string): string {
  const told = caught instanceof ApiError && caught.status >= 400 && caught.status < 500 ? caught.message : "";
  return `${lead} ${told || retry}`;
}
````
