# 다른 탭 로그아웃 동기화 구현 (F-06, `feat/F-06-signout-other-tabs`)

> 📝 기준: PRD v0.9 F-06 · API 명세 v0.4 4장(`DELETE /me`) · 이 문서의 9장(문서 반영)
> 적용할 곳: `main`(1c8a6da, #79 로그아웃) 위. 그 트리에서 만들고 시험했다.

한 탭에서 로그아웃·탈퇴해도 같은 브라우저의 다른 탭은 다음 요청이 401을 받을 때까지 개인 정보 화면(설정·플래너·공고 등)을 그대로 보여 줬다(#79 남은 일). 이제 다른 탭도 세션이 끝나는 순간 로그인 화면으로 간다. Supabase가 탭끼리 넘겨주는 `SIGNED_OUT`을 받아서 옮기고, 그 알림을 못 받은 탭(잠들었던 탭, 뒤로 가기로 복원된 화면)은 다시 보일 때 세션을 확인한다. 로그인 화면의 안내는 이유를 따른다. 다른 탭에서 로그아웃했으면 "로그아웃했어요", 탈퇴했으면 "탈퇴했어요", 이유를 모르면(로그인 만료) "로그인이 만료됐어요"다. 사용자가 고른 작업이고, 범위·안내는 사용자가 권장안을 골랐다(아래 1장).

| 값 | 결과 |
| --- | --- |
| 브랜치 | `feat/F-06-signout-other-tabs` |
| 파일 | 새 파일 1개(`web/src/lib/useSessionWatch.ts`), 고친 파일 4개(전부 web) |
| api·DB | 안 바뀜(새 API 없음, CI 1598 passed 그대로, 마이그레이션 없음) |
| web | `npm run typecheck`·`npm run build`(실제·목 모드) 통과 |
| 브라우저 | 실제 모드(가짜 GoTrue + 실제 API·DB) 30개 확인 · 목 모드 4개 — 5장 |
| 되돌림 시험 | 14개 중 14개를 브라우저 점검이 잡음 |

## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 범위: `SIGNED_OUT` + 다시 보일 때 확인 (사용자 선택, 권장) | `SIGNED_OUT`만 들으면 그 알림을 못 받은 탭(잠든 탭, 뒤로 가기 캐시로 복원된 화면, `BroadcastChannel`이 없는 브라우저)은 예전처럼 다음 401까지 남는다. `visibilitychange`(보이게 될 때)와 `pageshow`(캐시에서 복원될 때)에 `getSession()`으로 다시 본다. 세션이 없으면 로그인 화면, **다른 계정으로 바뀌었으면 홈**(새로 불러와 그 계정으로 다시 그린다 — 남의 화면 위에서 새 계정 토큰으로 요청하지 않게) |
| 안내: 이유별로 (사용자 선택, 권장) | supabase-js의 `SIGNED_OUT`에는 이유가 없다. 로그아웃·탈퇴하는 탭이 세션을 지우기 **직전에** 우리 채널(`BroadcastChannel("unipivot-auth")`)로 이유만 보낸다(`announceLeaving`). 다른 탭은 30초 안에 세션이 끝나면 그 이유로(`?notice=signed_out`·`deleted` — 그 탭이 쓰는 안내와 같다), 아니면 `?error=session`("로그인이 만료됐어요" — 지금 401과 같은 안내)으로 간다. 30초는 로그아웃 요청이 끊겨 supabase-js가 다시 해 보는 시간(25초쯤)보다 길게 잡았다. 채널에는 이유 글자만 실린다(토큰·사용자 정보 없음) |
| 이유는 "보내기 직전"에 | 푸시 정리(최대 3초)·`DELETE /me`가 끝난 뒤, Supabase 로그아웃 바로 앞에 보낸다. 탈퇴 API가 실패하면 아무것도 보내지 않는다. 보내고도 세션을 못 지우면(8초 안에 못 끝남) 다른 탭은 그대로 있고, 30초가 지나면 그 이유는 버린다 |
| 로그아웃하는 탭 자신도 감시를 끄지 않는다 | 처음엔 그 탭의 감시를 쉬게 했다(자기 흐름이 페이지를 옮기니까). 그런데 그 플래그가 모듈에 남아, 그 탭의 앞 기록이 뒤로 가기 캐시로 살아 돌아오면 확인을 건너뛰었다(독립 검토, 7장). 감시를 켜 둬도 그 탭은 자기 흐름과 같은 주소로 `replace`할 뿐이라(되돌림 시험으로도 차이가 없었다) 플래그를 없앴다. 이 탭도 이유를 기억하므로, 8초 안에 못 끝내 "로그아웃하지 못했어요"가 뜬 뒤에 세션이 끝나도 "로그아웃했어요"로 간다 |
| 이동은 `location.replace` | 지금 화면이 기록에 남지 않는다(뒤로 가기로 개인 정보 화면이 돌아오지 않게). 그보다 앞의 기록은 남는다 — 캐시로 복원되면 `pageshow`가 다시 확인하고, 새로 불러오면 401이 로그인 화면으로 보낸다 |
| 확인이 실패하면(오프라인 등) 내보내지 않는다 | supabase-js는 갱신이 실패해도 접근 토큰이 살아 있으면 저장된 세션을 그대로 준다. 토큰까지 만료됐으면 `{ session: null, error }`를 주는데, 이건 "세션 없음"이 아니라 "확인 못 함"이다. 노트북을 오프라인으로 깨웠을 때 로그인 화면으로 쫓아내지 않는다(다음 요청이 맡는다) |
| 이 화면의 사용자 | `INITIAL_SESSION`의 사용자로 잡는다. 처음에 세션을 못 불러왔으면(오프라인으로 열어 만료된 토큰을 갱신하지 못함) 나중에 세션이 실린 이벤트(`TOKEN_REFRESHED` 등)의 사용자로 잡는다(독립 검토). 처음부터 로그인 전인 화면은 지금처럼 `http.ts`(401)가 맡는다 |
| 어디서 | `AppFrame`(사이드바가 있는 모든 화면)과 온보딩(`screens/Onboarding.tsx` — 프로필을 입력하는 중인 화면). 로그인 화면은 감시하지 않는다(그대로 둔다) |
| 목 모드 | 아무것도 하지 않는다(세션이 없고 목 상태는 탭마다 따로다) |
| 새 API·필드 없음 | 브라우저 쪽만 바뀐다. 명세 머리말과 4장 탈퇴, PRD F-06에 한 줄씩 적는다(9장) |

## 3. 합친 뒤 확인

실제 Supabase로 한 번 본다. 같은 브라우저 창에 탭 두 개를 띄운다.

````text
1. 탭 1에 홈(/), 탭 2에 설정(/settings)을 연다.
   탭 2에서 설정 > 계정 > "로그아웃"을 누른다.
   → 탭 2는 로그인 화면 "로그아웃했어요. 다시 쓰려면 Google로 시작하기를 눌러 주세요."
   → 탭 1로 가 보면 이미 같은 로그인 화면이다(누르자마자 바뀐다). 탭 1에서 뒤로 가기를 눌러도 홈이 돌아오지 않는다.
2. 다시 로그인한 뒤 탭 두 개(홈·설정)를 다시 연다. 탭 1을 닫지 말고, 다른 프로그램 창으로 잠깐 옮겼다가
   돌아와도 아무 일 없이 그대로다(같은 계정이면 그대로 둔다).
3. (버리는 계정으로 탈퇴를 해 볼 때) 탭 1에 홈을 열어 두고 탭 2에서 탈퇴하면
   탭 1도 "탈퇴했어요. 개인 정보와 토큰, 올린 파일을 지웠어요."로 간다.
````

## 4. 구조

```text
lib/useSessionWatch.ts
  announceLeaving(reason)   로그아웃·탈퇴하는 탭이 세션을 지우기 직전에: 이유를 기억하고 BroadcastChannel("unipivot-auth")로 보냄
  useSessionWatch()         (실제 모드만)
    onAuthStateChange: INITIAL_SESSION → 이 화면의 사용자 / (사용자 모름 + 세션) → 그 사용자로
                       SIGNED_OUT → goToLogin() / 다른 사용자의 세션 → location.replace("/")
    visibilitychange(보임) · pageshow(persisted) → getSession() → 오류면 그대로, 세션 없음 → goToLogin(), 다른 사용자 → "/"
  goToLogin(): 30초 안에 들은 이유가 있으면 /login?notice=<이유>, 없으면 /login?error=session (location.replace)
components/AppFrame.tsx · screens/Onboarding.tsx ── useSessionWatch()
api/accountClient.ts  signOut(): 푸시 정리 → announceLeaving("signed_out") → supabase signOut(8초) → …
                      deleteAccount(): DELETE /me → announceLeaving("deleted") → supabase signOut → …
```

## 5. 확인한 것

시험 환경: 샌드박스 Postgres 16에 `auth_stub` → 마이그레이션 → `schema_checks`를 올리고 실제 API(HS256 비밀키)를 띄웠다. Supabase Auth는 가짜 GoTrue(로그아웃·토큰 갱신, 응답을 500·지연·갱신 거절로 바꿀 수 있음)로, 세션은 `sb-…-auth-token` 쿠키로 넣었다. 탭 두세 개는 같은 브라우저 컨텍스트(같은 쿠키·`BroadcastChannel`)의 페이지다. Chromium 헤드리스.

| 확인 | 결과 |
| --- | --- |
| `npm run typecheck` · `npm run build`(실제·목 모드) | 통과 |
| 로그아웃: 이 탭 / 다른 탭(홈·플래너) | 셋 다 `/login?notice=signed_out`, 다른 탭은 0.2초 안. 다른 탭 안내 "로그아웃했어요", 뒤로 가기로 홈이 안 돌아옴 |
| 탈퇴: 이 탭 / 다른 탭 | 둘 다 `/login?notice=deleted`, 다른 탭 안내 "탈퇴했어요" |

| 처음에 세션을 못 불러옴(만료 토큰, 갱신·API 둘 다 35초 끊김 — supabase-js 재시도보다 길게) → 다시 연결돼 자동 갱신 → 쿠키 사라짐 | 갱신된 세션을 이 화면의 사용자로 잡아, 보이게 되자 `/login?error=session` |

## 6. 되돌림 시험

코드를 하나씩 망가뜨려 빌드하고 위 브라우저 점검을 돌렸다. 처음엔 두 개가 빠져나갔는데 시험이 그 길을 타지 않아서였다. M7은 토큰이 살아 있으면 supabase-js가 오류 없이 세션을 줘서 토큰이 만료된 뒤에 확인하게 했다. M5는 갱신이 바로 성공하거나 API의 401이 먼저 와서 갱신·API를 35초 끊게 했다. 첫 판에서 "로그아웃하는 탭 감시 쉬기"를 뺀 돌연변이는 차이가 없어(같은 주소로 간다) 그 플래그를 없앴다(7장).

| 돌연변이 | 잡은 점검 |
| --- | --- |
| M1 감시 훅이 아무것도 안 함 | signout: other tab (home) -> notice=signed_out; signout: other tab (planner) -> notice=signed_out; signout: other tab shows 로그아웃했어요; expired: tab 1 -> error=session; expired: tab 2 -> error=session; expired: shows 로그인이 만료됐어요; missed: visibilitychange -> error=session |
| M2 로그아웃이 이유를 안 보냄 | signout: other tab (home) -> notice=signed_out; signout: other tab (planner) -> notice=signed_out; signout: other tab shows 로그아웃했어요 |
| M3 탈퇴가 `signed_out`을 보냄 | delete: other tab -> notice=deleted; delete: other tab shows 탈퇴했어요 |
| M4 이 탭이 보낸 이유를 기억 안 함 | slow: this tab follows later -> notice=signed_out |
| M5 처음 세션이 없을 때 나중 세션을 안 잡음 | late session: adopted, then watched |
| M6 `replace` 대신 `assign` | missed: replaced (back does not return); expired: replaced, not a 401 assign |
| M7 확인 오류를 세션 없음으로 봄(`if (!error)` 뺌) | offline: refresh fails -> stays |
| M8 다른 계정 확인 뺌 | switched: -> / (full load) |
| M9 `pageshow`에서 persisted를 안 봄 | pageshow(not persisted) ignored |
| M10 이유를 늘 지난 것으로 봄(30초 → 0) | signout: other tab (home) -> notice=signed_out; signout: other tab (planner) -> notice=signed_out; signout: other tab shows 로그아웃했어요; delete: other tab -> notice=deleted; delete: other tab shows 탈퇴했어요 |
| M11 온보딩에 감시 없음 | onboarding tab -> notice=signed_out |
| M12 `visibilitychange` 확인 뺌 | missed: visibilitychange -> error=session; switched: -> / (full load) |
| M13 `SIGNED_OUT`을 무시 | signout: other tab (home) -> notice=signed_out; signout: other tab (planner) -> notice=signed_out; signout: other tab shows 로그아웃했어요; delete: other tab -> notice=deleted; delete: other tab shows 탈퇴했어요; expired: tab 1 -> error=session; expired: tab 2 -> error=session; expired: shows 로그인이 만료됐어요 |
| M14 같은 사용자도 바뀐 것으로 봄 | same user: 설정을 열자 홈으로 계속 새로 불러와(7번) 설정 화면이 끝내 안 그려짐 |

## 7. 검토에서 고친 것

새 에이전트가 읽기만 하고 검토했다(auth-js 2.117.3 소스 대조).

| 지적 | 처리 |

export type LeaveReason = "signed_out" | "deleted";

const CHANNEL_NAME = "unipivot-auth";
const REASON_FRESH_MS = 30_000; // 로그아웃 요청이 끊겨 supabase-js가 다시 해 보는 시간(25초쯤)보다 길게

let channel: BroadcastChannel | null | undefined; // undefined: 아직 안 만듦, null: 브라우저에 없음
let lastReason: { reason: LeaveReason; at: number } | null = null;

function remember(reason: unknown): void {
  if (reason === "signed_out" || reason === "deleted") lastReason = { reason, at: Date.now() };
}

function authChannel(): BroadcastChannel | null {
  if (channel === undefined) {
    channel = typeof BroadcastChannel === "undefined" ? null : new BroadcastChannel(CHANNEL_NAME);
    channel?.addEventListener("message", (event: MessageEvent) => remember(event.data?.reason));
  }
  return channel;
}

// 이 탭이 세션을 지우기 직전에 부른다. 다른 탭에 이유를 알리고 이 탭도 기억한다(8초 안에 못 끝내 화면에 남았다가
// 나중에 세션이 끝나도 같은 안내로 간다)
export function announceLeaving(reason: LeaveReason): void {
  remember(reason);
  authChannel()?.postMessage({ reason });
}

function goToLogin(): void {
  const fresh = lastReason && Date.now() - lastReason.at < REASON_FRESH_MS ? lastReason.reason : null;
  window.location.replace(fresh ? `/login?notice=${fresh}` : "/login?error=session");
}

export default function useSessionWatch(): void {
  useEffect(() => {
    if (USE_MOCKS) return;
    const supabase = createBrowserSupabase();
    authChannel();
    let userId: string | null | undefined; // 이 화면을 그린 사용자. undefined면 아직 모른다

    const follow = (sessionUserId: string | null) => {
      if (!userId) return;
      if (sessionUserId === null) goToLogin();
      else if (sessionUserId !== userId) window.location.replace("/");
    };

    // 첫 세션이 없었는데(오프라인으로 열어 갱신을 못 함 등) 나중에 세션이 생기면 그 사용자를 이 화면의 사용자로 본다
    const { data } = supabase.auth.onAuthStateChange((event, session) => {
      if (event === "INITIAL_SESSION") userId = session?.user.id ?? null;
      else if (!userId && session) userId = session.user.id;
      else if (event === "SIGNED_OUT") follow(null);
      else if (session) follow(session.user.id);
    });

    // 다시 보일 때 확인한다. 갱신이 실패하면(오프라인 등) 세션이 없다고 보지 않는다 — 다음 요청이 맡는다
    const recheck = () => {
      if (document.visibilityState !== "visible" || !userId) return;
      void supabase.auth.getSession().then(({ data: current, error }) => {
        if (!error) follow(current.session?.user.id ?? null);
      });
    };
    const onPageShow = (event: PageTransitionEvent) => {
      if (event.persisted) recheck();
    };
    document.addEventListener("visibilitychange", recheck);
    window.addEventListener("pageshow", onPageShow);
    return () => {
      data.subscription.unsubscribe();
      document.removeEventListener("visibilitychange", recheck);
      window.removeEventListener("pageshow", onPageShow);
    };
  }, []);
}
