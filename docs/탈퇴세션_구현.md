## 3. 합친 뒤 확인

세션이 남는 경우는 손으로 만들기 어렵다(접근 토큰이 만료되는 순간 갱신 서버가 끊겨야 한다). 손으로는 평소 탈퇴가 그대로인지만 본다.

1. 버리는 계정으로 설정 → 탈퇴 → "탈퇴"를 입력하고 탈퇴 → 로그인 화면에 "탈퇴했어요"가 나오면 된다.
2. 뒤로 가기를 눌러도 설정 화면이 돌아오지 않으면 된다(전과 같다).

## 4. 구조

```text
Settings.removeAccount
  accountGone? ── 아니요 → deleteAccount(): DELETE /me → finishDeletion()
               └─ 예   → retryDeletion(): 세션을 불러오면(8초까지) deleteAccount(), 아니면 finishDeletion()
finishDeletion(): announceLeaving("deleted") → signOut(local) 8초까지(던져도 넘어감)
                  → 세션 쿠키가 남았으면 SessionLeftError, 아니면 /login?notice=deleted
catch: SessionLeftError(또는 accountGone) → "탈퇴는 끝났어요 …" + accountGone = true(이 화면이 떠 있는 동안)
       그 밖의 오류 → 전과 같은 "탈퇴하지 못했어요 …"
```

## 7. 검토에서 고친 것

새 에이전트가 읽기만 하고 검토했다(설치된 supabase-js의 `signOut` 코드까지 읽어, 세션이 남는 것은 세션을 불러오다 실패할 때뿐이라는 것을 확인했다).

| 지적 | 처리 |
| --- | --- |
| (낮음) `signOut`이 `{error}`를 돌려주지 않고 던지면 "탈퇴하지 못했어요"가 되고, 다음에 `DELETE /me`부터 다시 가 401 → 로그인 화면이 된다 | 던져도 넘어가고 쿠키만 본다 |
| (낮음) 창을 닫았다 다시 열면 "탈퇴는 끝났어요" 안내가 지워진다(15초 잠금이 풀린 뒤 닫으면 안내가 닫힌 창에 그려진다) | 탈퇴가 끝났으면 다시 열어도 남긴다(F6) |
| (낮음) 세션이 남은 채로 다른 탭에서 다시 동의한 뒤 이 탭에서 다시 누르면, 세션만 지우고 "탈퇴했어요"라고 한다 | 세션을 불러올 수 있으면 `DELETE /me`부터 다시 한다(F7) |
| (잔소리) 내보낸 함수에 목 모드 막이가 없다 | `retryDeletion`에 넣고, `finishDeletion`은 내보내지 않는다 |

검토가 문제없다고 본 것: `accountGone`은 이 화면에서 `DELETE /me`가 2xx로 끝난 뒤에만 켜진다(응답을 못 받은 것은 `NETWORK_ERROR`라 안 켜진다). 다른 화면으로 가면 화면이 내려가 잊는다. `announceLeaving`을 두 번 불러도 30초 창이 다시 시작될 뿐이다. 늦게 끝난 세션 지우기는 `useSessionWatch`가 "탈퇴했어요"로 옮긴다. 목 모드는 그대로다. 두 파일 모두 300줄 아래다.

## 8. 남은 것

- 세션이 남은 채로 설정 화면의 다른 일(알림 설정, 로그아웃의 푸시 정리)을 하면 토큰 없이 가서 401 → 그냥 로그인 화면이 된다(이 PR 전부터 있던 것. 세션 쿠키는 남는다).
