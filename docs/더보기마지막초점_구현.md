# 더 보기 마지막 쪽 초점 구현 (F-35·F-44, `fix/F-35-load-more-last-page-focus`)

> 📝 기준: web/CLAUDE.md(busy 규칙) · docs/더보기초점_구현.md "남은 것" 첫째·셋째 줄
> 적용할 곳: #75까지 합친 `main`(742f066) 위. 샌드박스에서 그 커밋 위에 그대로 만들고 시험했다.

문서함·알림함의 "더 보기"를 키보드로 누르면 이제 불러오는 동안 초점이 버튼에 남는다(#74). 그런데 **마지막 쪽**이 오면 버튼이 사라져 초점이 `<body>`로 떨어졌다. 이 PR은 그때 초점을 **새로 온 줄 중 화면의 첫 줄**로 옮기고, 다음 쪽 cursor가 맞지 않아(422) 목록을 처음부터 다시 받을 때는 **첫 줄**로 옮긴다. 화면 읽기 프로그램에는 늘 두는 `sr-only` 상태 줄로 "N개를 더 불러왔어요. 마지막 목록이에요." 같은 안내를 준다. 자리를 비운 동안 고른 것은 아래 "정한 것"에 적었다.

## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 공용 훅 `lib/useLoadMoreFocus.ts` 하나로 두 화면을 같이 | 화면마다 ref·effect를 따로 쓰면 422·탭 전환 같은 가장자리가 갈라진다. DOM(`focus`, `querySelector`)은 `src/lib`에만 둔다는 규칙에도 맞다 |
| 초점 대상: 새로 온 첫 줄(`data-row`) | 문서함은 줄(`<li tabIndex={-1}>`, 파일 이름·종류·받기 버튼을 한 번에 읽는다), 알림함은 알림 버튼 자체. 받기 버튼으로 바로 보내는 안(버린 것)은 "받기"만 읽혀 어느 파일인지 모른다 |
| 새 줄은 **화면 순서**로 찾는다 | 문서함은 과목별로 묶어 그려서 새 항목이 앞 과목 묶음 안에 들어갈 수 있다. 받은 순서로 고르면 그 위에 다른 새 줄이 남는다(검토). 목록 안의 `[data-row]`를 화면 순서로 읽어 새 id에 든 첫 줄을 고른다 |
| 더 보기가 남으면 초점은 버튼에 그대로 | #74의 `busy`가 이미 해 준다. 안내 문구만 바꾼다 |
| 누를 때 초점이 있었고 지금 `<body>`일 때만 옮긴다 | 그새 다른 곳으로 갔으면 두고(`lib/useCardFocus.ts`와 같은 규칙), 마우스로 눌러 처음부터 초점이 없던 때(Safari는 클릭으로 버튼에 초점을 주지 않는다)도 화면을 끌어 옮기지 않는다(검토) |
| 422로 다시 받으면 첫 줄, 알아보는 건 `generation` | `useDocuments`·`useNotifications`가 첫 쪽부터 다시 받은 횟수(`generation`, 기존 `round`)를 내보낸다. 다시 받은 첫 쪽이 앞과 똑같을 수 있고, 알림함은 목록을 비우지 않아서 "목록이 비었다"로는 알 수 없다(검토). 두 훅 모두 422에서 다시 받기 직전에 `loading`을 먼저 켜, 그 사이 그리기가 마지막 쪽처럼 보이지 않게 했다(문서함은 빈 문서함 안내가 잠깐 번쩍이던 것도 없어진다) |
| 빈 마지막 쪽(앞 쪽이 딱 끝에서 끊김) | 새 줄이 없으니 누르기 전의 마지막 줄로, "더 불러올 항목이 없어요. 마지막 목록이에요." |
| 실패하면 안내 줄에 오류 글 | 더 보기 버튼과 초점이 남아 다시 누르면 된다. 안내가 "불러오고 있어요"에서 오류 글로 바뀌어 같은 실패가 두 번 나도 다시 읽힌다(검토). 다시 받은 목록이 비거나 실패해도 안내를 끝낸다 |
| 알림함 탭을 바꾸면 누른 더 보기와 앞 안내를 잊는다(`listKey`) | 바뀐 목록의 첫 줄로 초점을 뺏지 않고, 앞 탭의 안내 문구가 남지 않는다 |
| 래퍼 `<div className="contents">` | 목록을 감싸 `querySelector` 범위를 정한다. `display: contents`라 화면 간격(부모의 `gap-7`)이 그대로다. 헤더 알림 패널에도 같은 `data-row`가 있지만 범위 밖이다 |

## 7. 검토에서 고친 것

새 에이전트(이 작업을 못 본)가 읽기만 해서 본 결과다. 연타·응답 순서·탭 전환·StrictMode·읽음 처리·`querySelector` 범위·`display: contents`·두 status 영역은 문제없었다.

| 지적 | 처리 |
| --- | --- |
| 높음 — 알림함은 422에서 목록을 비우지 않아 "다시 받음"을 못 알아보고 "마지막 목록"이라고 잘못 알린다 | 두 훅이 `generation`(다시 받은 횟수)을 내보내고, 422에서 `reload()` 직전에 `loading`을 켠다. 훅은 `generation`으로 다시 받음을 가린다. 브라우저 점검에 알림함 422를 더했다 |
| 중간 — 422 뒤 다시 받기가 실패하거나 비면 기다림이 끝나지 않는다 | `loading`이 끝나면 늘 끝낸다. 비었으면 오류 글이나 "목록을 처음부터 다시 받았는데 비어 있어요." |
| 중간 — 문서함은 받은 순서와 화면 순서가 달라 초점 대상이 어긋난다 | 목록 안 `[data-row]`를 화면 순서로 읽어 고른다 |
| 중간(추정) — `<body>`만 보면 마우스로 눌러 초점이 없던 때(Safari)도 화면을 끌어 옮긴다 | 누를 때 초점이 있었는지 기억하고 그때만 옮긴다. 점검에 "초점 없이 누름"을 더했다 |
| 낮음 — 같은 실패가 두 번이면 두 번째는 안 읽힌다 | 실패 때 안내 줄에 오류 글을 넣는다(앞의 `role="alert"` 추가는 뺐다 — 두 번 읽히지 않게) |
| 낮음 — `focus:`라 마우스로 줄 글자를 눌러도 테두리가 생긴다 | `focus-visible:`로 바꿨다 |
| 낮음 — 탭을 바꿔도 끝난 안내 문구가 남는다 | 탭(`listKey`)이 바뀌면 안내를 비운다 |
| 낮음 — 다음 쪽이 빈 배열인데 `next_cursor`가 있으면 실패로 본다(추정) | 그대로 둔다. 안내는 "더 불러오지 못했어요. 다시 눌러 주세요."이고 다시 누르면 된다. API는 빈 쪽에 cursor를 주지 않는다 |
| 낮음 — `ids`가 매 그리기 새 배열이라 effect가 매번 돈다, import 순서 | effect는 기다릴 것이 없으면 바로 끝나 그대로 둔다. `useCallback`은 뺐다. import는 맨 위로 옮겼다 |
| 참고 — 문서함 422 직후 빈 문서함 안내가 잠깐 보인다(기존) | `loading`을 먼저 켜서 같이 없어졌다(스켈레톤이 보인다) |

## 10. 코드와 패치

### 코드 (새 파일)

#### `web/src/lib/useLoadMoreFocus.ts`

````ts
import { useEffect, useRef, useState, type RefObject } from "react";

// "더 보기"를 누른 뒤의 초점과 화면 읽기 안내(문서함·알림함).
// 다음 쪽이 와도 더 보기가 남으면 초점은 그 버튼에 그대로 있다(Button의 busy). 마지막 쪽이라 버튼이 사라지면
// 초점이 <body>로 빠지므로, 새로 온 줄(data-row) 중 화면에서 첫 줄로 옮긴다. 다음 쪽의 cursor가 맞지 않아(422)
// 목록을 처음부터 다시 받으면(generation이 바뀐다) 화면의 첫 줄로 옮긴다.
// 초점은 누를 때 초점이 있었고(키보드) 지금 <body>로 빠졌을 때만 옮긴다 — 마우스로 눌러 초점이 없던 때(Safari)나
// 그새 다른 곳으로 간 때는 그대로 둔다. listKey가 바뀌면(알림함 탭) 앞 목록의 안내와 누른 더 보기를 잊는다
export interface LoadMoreFocus {
  status: string; // 늘 두는 sr-only role="status"에 넣는 글
  loadMore: () => void; // 화면의 더 보기 버튼에 준다
}

interface Options {
  listRef: RefObject<HTMLElement | null>;
  ids: string[]; // 지금 목록의 줄 id(받은 순서). 줄에는 data-row={id}를 단다
  loading: boolean; // 첫 쪽을 (다시) 받는 중
  loadingMore: boolean;
  hasMore: boolean;
  error: string | null;
  generation: number; // 첫 쪽부터 다시 받은 횟수(useDocuments·useNotifications)
  loadMore: () => void;
  listKey?: string;
}

interface Pending {
  ids: Set<string>; // 누를 때 이미 있던 줄
  last: string | undefined;
  generation: number;
  focused: boolean; // 누를 때 초점이 어딘가(그 버튼)에 있었는지
}

export default function useLoadMoreFocus(options: Options): LoadMoreFocus {
  const { listRef, ids, loading, loadingMore, hasMore, error, generation, loadMore, listKey } = options;
  const pending = useRef<Pending | null>(null);
  const [status, setStatus] = useState("");
  const [shownKey, setShownKey] = useState(listKey);

  // 목록이 바뀌면(탭) 앞 목록의 안내와 기다리던 더 보기를 버린다(그리는 중에 맞춘다)
  if (shownKey !== listKey) {
    setShownKey(listKey);
    setStatus("");
    pending.current = null;
  }

  const start = () => {
    if (!loadingMore && !loading && hasMore) {
      const doc = listRef.current?.ownerDocument;
      const active = doc?.activeElement;
      pending.current = { ids: new Set(ids), last: ids.at(-1), generation, focused: Boolean(active && active !== doc?.body) };
      setStatus("다음 쪽을 불러오고 있어요.");
    }
    loadMore();
  };

  useEffect(() => {
    const request = pending.current;
    if (!request || loading || loadingMore) return; // 아직 오는 중(422 뒤 다시 받는 첫 쪽 포함)
    pending.current = null;
    const restarted = generation !== request.generation;
    const fresh = new Set(ids.filter((id) => !request.ids.has(id)));
    let target: Target = null;
    if (restarted) {
      setStatus(ids.length > 0 ? "목록이 바뀌어 처음부터 다시 불러왔어요." : (error ?? "목록을 처음부터 다시 받았는데 비어 있어요."));
      if (ids.length > 0) target = "first";
    } else if (fresh.size === 0 && hasMore) {
      setStatus(error ?? "더 불러오지 못했어요. 다시 눌러 주세요."); // 실패. 버튼과 초점이 남아 있다
    } else if (fresh.size === 0) {
      setStatus("더 불러올 항목이 없어요. 마지막 목록이에요."); // 앞 쪽이 딱 끝에서 끊긴 때
      target = "last";
    } else {
      setStatus(hasMore ? `${fresh.size}개를 더 불러왔어요.` : `${fresh.size}개를 더 불러왔어요. 마지막 목록이에요.`);
      if (!hasMore) target = "fresh";
    }
    const list = listRef.current;
    if (!target || !list || !request.focused) return;
    const doc = list.ownerDocument;
    if (doc.activeElement && doc.activeElement !== doc.body) return; // 그새 다른 곳으로 갔다
    // 화면 순서로 찾는다(문서함은 과목별로 묶어 그려서 받은 순서와 다르다)
    const rows = [...list.querySelectorAll<HTMLElement>("[data-row]")];
    const row =
      target === "first"
        ? rows[0]
        : target === "fresh"
          ? rows.find((element) => fresh.has(element.dataset.row ?? ""))
          : rows.find((element) => element.dataset.row === request.last);
    row?.focus();
  }, [error, generation, hasMore, ids, listRef, loading, loadingMore]);

  return { status, loadMore: start };
}
````
