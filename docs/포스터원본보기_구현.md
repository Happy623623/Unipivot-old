# 포스터 원본 보기 구현 (W6, `feat/F-16-poster-original`)

> 📝 기준: PRD v0.9 F-41 · API 명세 v0.4 5장 · 이 문서의 9장(명세·PRD 반영)
> 적용할 곳: `main` 위에서 `feat/F-44-recorded-signed-url`(녹화저장소받기주소) **다음**에 적용한다. 샌드박스에서는 그 PR까지만 얹은 트리에서 만들고 시험했다 — `문서함받기`(1)·`더보기초점`(2)·`로그가림repr`(4)·`저장소주소모양`(5)와 같은 줄을 고치면 `git apply`가 막힐 수 있다(아래 "적용 순서").

내가 올린 포스터 공고의 **원본**(사진·PDF)을 공고 상세의 "원문 보기"에서 볼 수 있게 한다. 상세 응답의 `poster_url`(늘 null이던 자리)을 `poster_kind`(`image`·`pdf`·`null`)로 바꾸고, 주소는 누를 때 `GET /opportunities/{id}/poster-url`로 따로 받는다(5분, `no-store`). 사진은 창 안에서, PDF는 새 탭 링크로 연다. 자리를 비운다고 해서 아래 "정한 것"은 묻지 않고 추천 방향으로 골랐다.

## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 상세 응답에는 주소가 아니라 `poster_kind`만 둔다 | (a) 상세에서 바로 서명 주소를 채우면, 요청의 DB 연결을 잡은 채 저장소 서명을 기다리게 된다. 상세는 주소를 쓰지 않는 사람에게도 매번 서명하게 된다 |
| 주소는 `GET /opportunities/{id}/poster-url`로 누를 때 받는다 | (c) API가 302로 저장소에 보내는 방식은 `<img>` 요청에 `Authorization` 머리값이 안 실려 쓸 수 없다 |
| 내가 올린 포스터 공고 + 내 파일만 | 남이 올린 포스터의 원본은 공유(P1)에서 정한다. 남의 포스터·포스터가 아닌 공고·원본이 없는 공고는 `poster_kind`가 null이고 주소 요청은 404다 |
| 형식은 올릴 때 바이트로 가린 JPEG·PNG·WEBP→`image`, PDF→`pdf`, 그 밖은 null | 화면이 형식을 모르면 사진 창에 PDF를 넣게 된다. 모르는 형식은 원문 보기를 숨기는 쪽(안전한 쪽)으로 실패한다 |
| 서명 주소에 `download`를 붙이지 않는다 | 브라우저가 그대로 보여 주려면 attachment가 아니어야 한다. 포스터는 업로드가 바이트로 JPEG·PNG·WEBP·PDF만 받고 저장소 Content-Type도 그 바이트로 가린 값이라 inline으로 열어도 HTML·SVG가 실행될 길이 없다(문서함 받기는 형식을 안 가려서 늘 이름을 넘긴다) |
| 404·502 규칙은 문서함 받기와 같다 | 기록은 있는데 저장소에 없으면 404 + "포스터를 다시 올려 주세요". 단 저장소 설정에 고칠 점이 있으면(`storage_settings_problem`) 그 "없음"을 믿지 않고 502다 |
| DB 연결은 파일을 찾을 때만 빌린다 | 서명하는 동안 풀의 연결을 쥐고 있지 않게 한다(저장소가 느려도 다른 요청이 안 막힌다) |
| 응답에 `Cache-Control: no-store`, 주소는 로그에 남기지 않는다 | 주소는 5분짜리 열쇠다 |
| 화면은 열 때 받고 닫으면 버린다 | 주소를 들고 있지 않는다. 다시 열면 새로 받는다 |
| 사진은 창 안 `<img>`, PDF는 "새 탭에서 PDF 열기" 링크 | 주소를 받은 뒤에 사용자가 누르게 해 팝업 차단을 피한다. 링크는 `rel="noopener noreferrer"`이고, 4분 30초 뒤에는 "시간이 지났어요" + 다시 불러오기로 바꾼다 |
| 공고 상태(숨김·병합)는 보지 않는다 | 내가 올린 내 파일이다. 숨긴 포스터도 원본을 받을 수는 있다(상세를 못 여는 것과 별개). 리뷰에서 나온 낮은 위험으로 판단해 그대로 둔다 |
| 목 모드 | `getPosterUrl`이 예시 포스터 그림을 준다. 개발 시나리오 `poster_gone`("포스터 원본 없음")을 더했다 |

## 3. 합친 뒤 확인

실제 Supabase에서 한 번 본다. 가짜 저장소로는 "서명 주소를 `download` 없이 열면 inline으로 오는지"와 `<img>`로 읽히는지를 확신할 수 없다. 로그인한 브라우저에서 개발자 도구 → 네트워크의 요청 머리값에서 `Authorization: Bearer …` 뒤의 토큰을 복사해 **내 PowerShell에서만** 환경 변수로 둔다(채팅에 붙이지 않는다).

```powershell
$env:UNIPIVOT_TOKEN = Read-Host "토큰"   # 붙여 넣고 Enter. 이 창에서만 쓰고 닫는다
$h = @{ Authorization = "Bearer $env:UNIPIVOT_TOKEN" }
$api = "http://localhost:8000/api/v1"
$id = Read-Host "내가 올린 포스터 공고 id"

# 1) 상세는 주소 없이 형식만 준다
$d = Invoke-RestMethod "$api/opportunities/$id" -Headers $h
"poster_kind -> $($d.poster_kind)"

# 2) 주소를 따로 받는다 (5분, no-store)
$r = Invoke-WebRequest "$api/opportunities/$id/poster-url" -Headers $h
"cache-control -> $($r.Headers['Cache-Control'])"
$u = ($r.Content | ConvertFrom-Json)
"url host path -> " + ([uri]$u.url).Host + ([uri]$u.url).AbsolutePath.Substring(0, 24)
"download in url -> " + ($u.url -match "download=")
"expires_at -> $($u.expires_at)"

# 3) 그 주소를 연다 — 내려받기가 아니라 그대로 보여 주는 응답이어야 한다
$f = Invoke-WebRequest $u.url
"status -> $($f.StatusCode)  type -> $($f.Headers['Content-Type'])  disposition -> $($f.Headers['Content-Disposition'])"

# 4) 남의 공고 id로 부르면 404
try { Invoke-WebRequest "$api/opportunities/00000000-0000-4000-8000-000000000000/poster-url" -Headers $h } catch { "other -> " + $_.Exception.Response.StatusCode.value__ }
```

예상 출력(사진 포스터일 때):

```text
poster_kind -> image
cache-control -> no-store
url host path -> <프로젝트>.supabase.co/storage/v1/object/sign
download in url -> False
expires_at -> 2026-…T…+09:00
status -> 200  type -> image/png  disposition ->
other -> 404
```

- `disposition ->` 뒤가 **비어 있어야** 한다. `attachment…`가 나오면 저장소가 `download` 없이도 attachment를 붙이는 것이라 알려 달라.
- PDF 포스터면 `poster_kind -> pdf`, `type -> application/pdf`다.
- 화면에서: 내가 올린 포스터 공고 → "원문 보기"를 누르면 사진은 창 안에, PDF는 "새 탭에서 PDF 열기" 링크가 나온다. 창을 닫았다 다시 열면 주소를 새로 받는다(네트워크 탭에 `poster-url` 요청이 또 보인다).

## 4. 구조

```text
GET /opportunities/{id}/poster-url
  routers/opportunities.py::read_poster_url
    └ repositories/files.py::FileRepository.poster(user_id, opportunity_id)   # DB 연결은 여기서만
        └ opportunities.POSTER_OWN / POSTER_FORMAT   # 상세의 poster_kind와 같은 소유 조건
    └ storage.signed_url(path)                       # download_name 없이 → 그대로 보는 주소
    └ 404 NOT_FOUND / 502 STORAGE_API_ERROR / Cache-Control: no-store

공고 상세 poster_kind = repositories/opportunities.py::POSTER_KIND (서브쿼리, 행 수를 안 바꾼다)

web
  OpportunityDetail ── (poster_kind 있으면) 원문 보기 ──> PosterOriginal(opportunityId, kind)
    PosterOriginal ── getPosterUrl()[posterClient.ts] ──> image: <img> / pdf: ButtonLink(새 탭)
    닫으면(조각이 사라지면) 주소를 버린다. 4분 30초 뒤 PDF 링크를 내린다
```

- `SupabaseStorage.signed_url(path, *, download_name=None)`: 이름이 없으면 `download`를 붙이지 않는다. 문서함 받기는 늘 이름을 넘긴다.
- `RecordedStorage.signed_url`도 같다(`signed` 기록의 이름이 `str | None`).
- 새 클래스 `PosterOriginalFile(storage_path, kind)`는 `repositories/files.py`에 둔다(`repositories/posters.py`의 `PosterFile`과 이름이 겹치지 않게 다르게 지었다).

## 7. 검토에서 고친 것

새 에이전트(이 작업을 못 본)가 읽기만 해서 본 결과다. 보안(남의 공고·파일로 주소가 나가는 길, 로그·오류 본문의 주소, `download` 없는 inline의 안전성)과 정확성(행 수, null·변형 mime, 같은 파일을 쓰는 두 공고)은 막을 결함이 없었다.

| 지적 | 처리 |
| --- | --- |
| 높음 — 명세·PRD에 `poster_url`→`poster_kind`, 새 엔드포인트가 없다 | 9장에 반영 글을 넣었다(명세 6곳·PRD 2곳) |
| 중간 — 다시 불러오기를 누르면 버튼이 사라져 초점이 body로 빠진다 | 창 내용에 `tabIndex={-1}`을 주고 누를 때 거기로 초점을 옮긴다. 공용 `Modal`의 초점 가두기·Esc는 이전부터의 일이라 이 PR에서 건드리지 않았다(8장) |
| 낮음 — `PosterFile`이 `repositories/posters.py`에도 있다 | `PosterOriginalFile`로 바꿨다 |

## 8. 남은 것

- 남이 올린 포스터의 원본은 공유(P1)에서 정한다.
- 공용 `Modal`에 초점 가두기·Esc·닫을 때 원래 버튼으로 돌아가기가 없다(이전부터). 다른 창과 같이 고치는 작은 web PR이 맞다.
- PDF 만료를 `expires_at` 기준으로 내리기(현재는 응답 시각 + 4분 30초).
- 내가 직접: 3장 확인(실제 Supabase에서 `<img>`로 읽히는지, PDF 새 탭).

      ({ url }) => {
        if (!alive) return;
