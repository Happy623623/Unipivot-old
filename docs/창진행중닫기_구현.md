# 창 진행 중 닫기 잠금 구현 (F-06, `feat/F-06-modal-busy-close`)

> 📝 기준: docs/창초점_구현.md 8장("진행 중엔 닫기를 막을지 따로 정한다") · 이 문서의 9장(구현 기록 반영)
> 적용할 곳: `main`(c0b89b0, #81 알림 패널 초점) 위. 그 트리에서 만들고 시험했다.

저장·탈퇴·연결 해제처럼 창 안의 일이 진행 중일 때도 Esc·×·덮개·취소로 창이 닫혔다. 닫힌 뒤 실패하면 오류가 닫힌 창 안에 그려져 끝내 보이지 않았다(탈퇴는 실패했는지조차 모른다). 이제 진행 중엔 닫히지 않고, ×·취소는 `aria-disabled`로 알린다. 다만 API 요청에는 시간 제한이 없어 응답이 멈추면 창에 갇히므로, 같은 일이 15초를 넘기면 잠금을 푼다. 사용자가 고른 작업이고, 방식은 사용자가 권장안("막되 15초 뒤 풀기")을 골랐다. 하면서 드러난 것 둘도 같이 고쳤다. 연결 해제 버튼에 진행 중 표시가 없어 두 번 보내지던 것, 전역 CSS 때문에 버튼의 커서 클래스가 하나도 먹지 않던 것이다.

## 1. 정한 것

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| 막되 15초 뒤 풀기 (사용자 선택, 권장) | 진행 중엔 Esc·×·덮개·취소를 모두 무시한다. 같은 일이 15초를 넘기면 풀린다(요청이 멈춰도 새로고침 말고 나갈 길을 남긴다). 풀린 뒤 닫으면 그 결과는 볼 수 없다. 진행 중 버튼은 그대로 busy다. 버린 것: 완전히 막기(멈춘 요청에 갇힌다), 닫게 두고 토스트로 알리기(창마다 성공·실패 문구를 따로 달아야 한다) |
| `Modal`에 `busy` 하나 | 창마다 따로 막지 않는다. `busy`를 넘기면 `Modal`이 닫기 요청을 거른다(`lib/useCloseLock.ts`). 초점 훅(`useDialogFocus`)은 고치지 않고 거른 닫기를 넘긴다 |
| 15초는 일 하나에 한 번 | `busy`가 켜진 때부터 센다. 풀린 뒤 닫았다가 아직 진행 중에 다시 열어도 새로 세지 않는다(검토). `busy`가 꺼지면 되돌려 다음 일은 다시 잠근다 |
| 취소는 `ModalCancelButton` | 창 안의 취소가 닫기 잠금을 따른다(창이 컨텍스트로 알려 준다). 프로필 수정 창의 취소는 `ProfileForm` 안에 있어 `useModalCloseLocked()`로 같은 값을 읽는다(창 밖 온보딩에서는 늘 false) |
| `Button`에 `inactive` | 잠긴 취소는 "다른 일이 진행 중이라 못 누름"이다. `busy`처럼 `aria-disabled`를 달고 누름을 무시하며 초점도 남지만, `aria-busy`는 달지 않는다(취소 자체가 진행 중인 게 아니다). `disabled`는 초점이 빠져서 쓰지 않는다(web 규칙) |
| × 버튼 | 잠기면 `aria-disabled`, 커서 not-allowed, `title` "진행 중인 일이 끝나면 닫을 수 있어요". 초점은 받을 수 있다 |
| 적용한 창 8곳 | 탈퇴·프로필 수정(설정), 정보 입력(공고 상세 — 저장·소득 동의 둘 다), 소득 동의 철회, Google Calendar·LearningX 연결 해제, LearningX 연결(확인 중), 플래너 일정 추가·수정. "그래도 준비하기"는 누르면 먼저 창을 닫고 오류도 창 밖에 띄우며, 포스터 원문은 불러오기뿐이라 넣지 않았다(신고 창은 쓰는 곳이 없다) |
| 연결 해제 버튼에 busy | 두 연결 해제는 진행 중 표시가 없어 누를 때마다 요청이 갔다. "해제하는 중" + busy로 바꾸고 창도 잠근다 |
| 늦게 온 결과가 다시 연 창을 건드리지 않게 | 15초 뒤 닫고 다시 열었을 때다. LearningX 연결 창은 닫을 때마다 회차를 올려, 앞 요청의 결과(성공·실패 화면, 토큰 지우기)는 새 창에 그리지 않는다. 연결 상태(바깥)에는 그대로 알린다. 플래너는 창을 연 회차가 같을 때만 저장 뒤 창을 닫는다. 둘 다 검토에서 나왔다 |
| LearningX "확인 중" 화면으로 초점 | "연결하기"가 확인 화면으로 바뀌면서 초점이 `<body>`로 빠졌다. 창이 키를 못 들어 15초 뒤에도 Esc로 닫을 수 없었다(검토가 짚은 원래 있던 문제, 이번 잠금으로 드러남). 확인 화면(`role="status"`, `tabIndex=-1`)으로 옮긴다 |
| 전역 `button { cursor: pointer }`를 `@layer base`로 | 층 밖 규칙은 Tailwind 유틸리티(utilities 층)를 늘 이긴다. 그래서 `aria-disabled:cursor-wait`, `disabled:cursor-not-allowed`, 창 덮개의 `cursor-default` 같은 커서가 지금까지 하나도 먹지 않았다. base 층으로 옮기면 기본은 그대로 pointer이고 유틸리티가 이긴다. 그 바람에 순서가 드러난 계획서 "캘린더에 넣기"의 커서도 고쳤다(`not-aria-busy`, 검토) |
| 새 API·문서 없음 | PRD·명세는 창 동작을 다루지 않는다. 창초점 구현 기록의 해당 세 줄과 web/CLAUDE.md만 고친다 |

## 3. 합친 뒤 확인

실제 Supabase로 본다. 진행 중 상태를 오래 보려면 브라우저 개발자 도구 > Network > 속도 제한(Slow 3G 등)을 켠다.

````text
1. 설정 > 연결된 서비스에서 LearningX(또는 Google Calendar)가 연결돼 있으면 "연결 해제" → 창의 "연결 해제".
   누르자마자 버튼이 "해제하는 중"이 되고, 그동안 Esc·×·바깥 누르기·취소로 창이 닫히지 않는다.
   끝나면 창이 닫힌다(실패하면 창 안에 "연결을 해제하지 못했어요"). 연결이 없으면 2번만 본다.
2. 설정 > 프로필 수정 → 저장. "저장 중"인 동안 × 위에 마우스를 올리면 "진행 중인 일이 끝나면 닫을 수 있어요".
3. 아무 버튼에나 마우스를 올려 손가락 커서, 진행 중 버튼(저장 중 등)에는 모래시계 커서가 나오는지.
````

## 4. 구조

```text

                         locked = useCloseLock(busy) && open → close() = locked면 무시, 아니면 onClose
                         useDialogFocus(…, close) · 덮개 onClick=close · × onClick=close aria-disabled={locked}

## 5. 확인한 것

시험 환경은 앞 PR들과 같다(Postgres 16 e2e DB, 실제 API, 가짜 GoTrue, Chromium 헤드리스). 진행 중 상태는 Playwright 라우트로 요청을 붙잡아 두었다가 원하는 때 500·422·201로 답하게 해서 만들었다. 연결됨 상태(캘린더·LearningX·소득 동의)는 `GET /me`·`GET /lms/connection` 응답을 바꿔 만들었다. 정보 입력 창은 공고가 목데이터에 있어 목 모드로 봤다(목 호출은 300ms 걸린다 — 누르고 한 프레임 뒤 Esc·×).

| 확인 | 결과 |
| --- | --- |

## 7. 검토에서 고친 것

새 에이전트가 읽기만 하고 검토했다. 막을 문제는 없다고 봤고, 대부분 "15초 뒤 풀린 다음"의 가장자리 경우를 짚었다.

| 지적 | 처리 |
| --- | --- |
| (중간) LearningX 연결: 풀린 뒤 닫으면 `close()`가 상태를 처음으로 돌리는데 요청은 계속 간다 — 다시 열어 또 보내기, 앞 요청이 새 토큰을 지움, 옛 결과가 다음 3단계에 뜸 | 닫을 때마다 회차를 올리고 같은 회차일 때만 창 상태를 바꾼다(B22·B23). 연결 상태는 바깥에 그대로 알린다. 다시 열어 또 보내는 것은 막지 않는다(앞 요청을 버린 뒤라 사용자가 고른 일이다) |

import { useEffect, useState } from "react";

// 창 안의 일(저장·탈퇴·연결 해제 등)이 진행 중이면 창을 닫지 못하게 잠근다(components/Modal.tsx의 busy).
// 닫힌 뒤에 실패하면 오류가 닫힌 창 안에 그려져 보이지 않아서다. 다만 요청에는 시간 제한이 없어, 응답이 멈추면 창에
// 갇힌다. 그래서 같은 일이 15초를 넘기면 잠금을 푼다(그 뒤에 닫으면 결과는 볼 수 없다 — 진행 중 버튼은 그대로 busy다).
// 15초는 busy가 켜진 때부터 센다(창을 닫았다 열어도 새로 세지 않는다)
export const CLOSE_LOCK_MS = 15_000;

export default function useCloseLock(busy: boolean, ms: number = CLOSE_LOCK_MS): boolean {
  const [expired, setExpired] = useState(false);

  useEffect(() => {
    if (!busy) {
      setExpired(false); // 다음 일은 다시 잠근다
      return;
    }
    const timer = setTimeout(() => setExpired(true), ms);
    return () => clearTimeout(timer);
  }, [busy, ms]);

  return busy && !expired;
}
````
