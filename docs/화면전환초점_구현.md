# 화면 전환 초점 구현 (F-35·F-06, `feat/F-35-route-focus`)

> 📝 기준: docs/알림패널초점_구현.md 8장 · docs/창진행중닫기_구현.md 8장 · 이 문서의 9장(구현 기록 반영)

두 가지 초점 문제를 고친다.

1. **화면 전환 뒤 초점**: 알림 줄·"모든 알림 확인하기"·공고 카드처럼 누른 것이 화면과 함께 사라지면, 새 화면에서 초점이 페이지 맨 처음(`<body>`)에 남았다. 키보드 사용자는 Tab을 처음부터 다시 눌러야 했고, 화면 읽기 프로그램은 새 화면 이름을 읽지 않았다. 이제 새 화면 제목(h1)으로 옮긴다.
2. **Safari에서 연 창**: Safari·macOS Firefox는 버튼을 마우스로 눌러도 버튼에 초점을 주지 않는다. 그래서 창을 연 버튼을 몰라, 닫아도 그 버튼으로 돌아가지 못했다(앞 문서들의 남은 것). 이제 방금 누른 버튼을 연 버튼으로 본다.

## 1. 정한 것 (사용자 부재 — 모두 권장안)

| 고른 것 | 이유 · 버린 선택지 |
| --- | --- |
| **초점이 빠졌을 때만** 새 화면 제목으로 | 사이드바 버튼처럼 누른 것이 남아 있으면 그대로 둔다. 그 버튼을 다시 누르거나 다음으로 Tab하는 흐름을 깨지 않는다. 화면을 옮길 때마다 늘 제목으로 보내는 안은 사이드바 사용 흐름을 바꾸고, 화면 읽기 프로그램이 매번 제목부터 읽게 해서 버렸다. 처음 열 때(새로고침·주소 입력)와 경로가 같을 때(쿼리만 바뀜)도 그대로 둔다 |
| 제목은 `main h1` 하나 | 사이드바가 있는 화면은 모두 `Header`가 h1을 그린다(9개 화면). `tabIndex=-1`(Tab 순서에는 안 넣음)과 다른 곳과 같은 `focus-visible` 테두리를 준다 |
| 제목이 생길 때까지 3초 기다린다 | 화면이 데이터를 받은 뒤에 `Header`를 그리기도 한다(공고 상세는 그동안 뼈대만 보인다). 다음 프레임마다 다시 본다. 보이는 제목에 초점이 실제로 가야 끝낸다. 그동안 사용자가 다른 곳에 초점을 두면 그만둔다. 3초가 넘게 걸리면 옮기지 않는다(8장) |
| 창이 열려 있으면 옮기지 않는다 | `?focus=profile_input`으로 바로 열리는 정보 입력 창은 창이 초점을 맡는다. 창이 초점을 잡기 전 한 프레임에 제목이 끼어들면 창의 돌아갈 곳이 바뀌어서(검토), 창이 열려 있으면 기다리지도 않는다 |
| StrictMode에서도 맞게 | "처음인지" 대신 이전 경로와 비교한다(검토) |
| Safari: 1초 안에 누른 버튼을 연 버튼으로 | 창을 열 때 초점이 `<body>`면, 그 직전 `pointerdown`으로 기억한 버튼·링크(`button`·`a[href]`·`[role=button]`)를 연 버튼으로 본다. 1초가 넘은 누름, 창 안의 버튼, 이미 떼어진 요소는 쓰지 않는다. 한 번 누름은 창 하나에만 쓰고 비운다. `pointerdown`은 한 번만 건다. 버린 것: 창을 여는 곳마다 `returnFocusRef`를 넘기기(열 곳이 많고 새로 생길 때마다 빠진다) |
| 고친 곳은 `useDialogFocus` 하나 | `Modal`과 헤더 알림 패널이 같이 쓴다. 알림 패널은 이미 종을 `returnFocusRef`로 넘기고 있어 그대로 둔다 |

## 3. 합친 뒤 확인

키보드로 본다.

````text
1. 아무 화면에서 Tab으로 종 → Enter → Tab을 "모든 알림 확인하기"까지 → Enter
   → 알림 화면으로 가고 "알림" 제목에 초점 테두리가 있다. 다음 Tab은 알림 화면 안에서 이어진다.
2. 알림 화면에서 공고로 가는 알림 줄을 Tab으로 골라 Enter → 공고 상세의 제목에 초점이 있다.
3. 사이드바 "문서함"을 Tab으로 골라 Enter → 문서함으로 가도 초점은 사이드바 "문서함"에 남는다.
4. (Safari가 있으면) 설정 > 계정 > "탈퇴"를 마우스로 눌러 창을 열고 Esc → "탈퇴" 버튼에 초점 테두리가 있다.
````

## 7. 검토에서 고친 것

새 에이전트가 읽기만 하고 검토했다.

| 지적 | 처리 |
| --- | --- |
| (중간) 옮겨 간 화면에서 창이 바로 열리면(`?focus=profile_input`), 데이터가 온 커밋과 창이 초점을 잡는 효과 사이의 한 프레임에 제목이 끼어들 수 있다. 그러면 창의 연 버튼이 제목이 되어 닫으면 "AI 자격 판정"이 아니라 화면 제목으로 간다 | 열린 창(`role="dialog"`·`aria-modal`·`inert` 아님)이 있으면 옮기지 않는다. 점검 "옮겨 간 화면의 창"은 통과하지만, 헤드리스에서는 경쟁 자체가 재현되지 않아 이 줄을 빼도 통과한다(R6) |
| (낮음~중간) "처음인지" 플래그는 StrictMode(개발 서버)가 효과를 한 번 더 돌리면 처음 열 때도 옮긴다 | 이전 경로와 비교한다. 정리에서 프레임을 취소해도 다시 돈 효과가 이어서 기다리게, 옮길 일을 ref에 둔다. `next dev`로 처음 열기·이동·창 세 점검을 따로 돌려 통과했다 |
| (낮음) 제목을 찾으면 초점이 실제로 갔는지 안 본다. 이전 화면을 숨겨 남기는 설정이 켜지면 숨은 옛 제목이 먼저 잡힌다 | 보이는 제목만 고르고, 초점이 실제로 갔을 때만 끝낸다 |
| (낮음) 주석의 "사이드바는 그대로"는 Chrome 이야기다. Safari는 누른 버튼에 초점이 없어 사이드바로 옮겨도 제목으로 간다 | 주석과 web/CLAUDE.md에 적었다(해롭지 않다 — 마우스라 테두리도 안 보인다) |
| (낮음) 오류 화면·뼈대에는 제목이 없어, 3초 넘게 걸리면 초점이 `<body>`에 남는다 | 8장 |
| (낮음) 기억한 누름을 다음 누름까지 붙잡고, 한 번 누름이 두 창에 쓰일 수 있다 | 쓰면 비운다. 1초 점검은 "누른 지 1초 뒤에 열린 창"으로 바꿔 돌렸다(R8) |
| (낮음) Safari에서 `tabIndex=-1` 조상 안의 버튼을 누르면 초점이 조상으로 가서 그 조상이 연 버튼이 된다 | 그대로 둔다. 지금은 창 안에서 다른 창을 여는 흐름이 없다 |

검토가 문제없다고 본 것은 다음과 같다.
- **화면 이동 순서**: Next 16.4는 화면을 옮길 때 초점을 건드리지 않는다. 옛 화면을 유지하다가 새 화면과 경로를 같은 커밋에 반영해서, 효과가 돌 때 옛 제목은 이미 없다.
- **알림 패널에서 옮길 때**: 패널이 닫히며 종으로 돌아갔다가, 종이 옛 헤더와 함께 사라져 `<body>`가 된 뒤 새 제목으로 간다. Safari에서는 누른 줄이 패널과 함께 사라져 대체 연 버튼이 끼어들지 않는다.
- **플래너 메뉴와 제목**: 플래너 "⋯" 메뉴에서 연 창은 `returnFocusRef`를 그대로 쓴다. 모든 화면에서 `main h1`은 하나다.
- **그 밖**: 터치(iOS Safari도 탭한 버튼에 초점이 없다), SSR, 규칙(document는 lib에서만)도 문제없다.

## 8. 남은 것

- 제목이 3초 넘게 늦게 그려지는 화면(느린 연결)에서는 초점을 옮기지 않는다
- 사이드바로 옮겼을 때 화면 읽기 프로그램은 새 화면 이름을 읽지 않는다(초점이 사이드바에 남는다). 필요하면 화면 이름을 읽어 주는 live 영역을 더한다
- `/notifications` 화면과 헤더 패널의 목록 동기화, 15초 뒤 닫은 일의 결과 알리기(인수인계 7장)

````ts
import { useEffect, useRef } from "react";

// 다른 화면으로 옮기면(주소의 경로가 바뀜) 누른 것(알림 줄·"모든 알림 확인하기"·공고 카드 등)이 사라져 초점이 <body>로
// 빠진다. 새 화면의 제목(main의 h1)으로 옮겨 화면 읽기 프로그램이 새 화면 이름을 읽고, Tab이 그 화면에서 이어지게 한다.
// 처음 열 때와, 누른 것에 초점이 아직 남아 있을 때(Chrome에서 사이드바 버튼을 누름)는 그대로 둔다 — Safari·macOS
// Firefox는 마우스로 누른 버튼에 초점을 주지 않아 사이드바로 옮겨도 제목으로 간다(마우스라 테두리는 안 보인다).
// 새 화면은 데이터를 받은 뒤에 제목을 그리기도 해서, 제목이 생길 때까지 조금(최대 WAIT_MS) 기다린다.
// 기다리는 동안 사용자가 다른 곳에 초점을 두거나 창이 열리면(?focus=profile_input으로 바로 열리는 정보 입력 창 —
// 창이 초점을 잡기 전 한 프레임에 제목이 끼어들면 창의 돌아갈 곳이 바뀐다, 검토) 그만둔다
const WAIT_MS = 3000;

function focusLost(): boolean {
  return document.activeElement === document.body || document.activeElement === null;
}

// 열린 창(닫힌 알림 패널은 inert라 빠진다)
function dialogOpen(): boolean {
  return document.querySelector('[role="dialog"][aria-modal="true"]:not([inert])') !== null;
}

export default function useRouteFocus(pathname: string): void {
  // 이전 경로와 비교한다. "처음인지" 플래그는 StrictMode(개발)가 효과를 한 번 더 돌리면 처음에도 옮겨 버린다(검토)
  // 옮길 일이 남은 경로. StrictMode가 효과를 지웠다 다시 돌려도(정리에서 프레임을 취소한다) 이어서 기다린다
  const previous = useRef(pathname);
  const pending = useRef<{ pathname: string; startedAt: number } | null>(null);

  useEffect(() => {
    if (previous.current !== pathname) {
      previous.current = pathname;
      pending.current = { pathname, startedAt: Date.now() };
    }
    const job = pending.current;
    if (!job || job.pathname !== pathname) return;
    const { startedAt } = job;
    let frame = 0;
    const done = () => {
      if (pending.current === job) pending.current = null;
    };
    const tryFocus = () => {
      // 누른 것이 남았거나, 사용자가 이미 다른 곳에 있거나, 창이 맡는다
      if (!focusLost() || dialogOpen()) return done();
      // 보이는 제목만(이전 화면을 숨겨 남기는 설정이 켜지면 숨은 옛 제목이 먼저 잡힌다, 검토)
      const heading = [...document.querySelectorAll<HTMLElement>("main h1")].find(
        (element) => element.getClientRects().length > 0,
      );
      heading?.focus({ preventScroll: true });
      if (document.activeElement === heading) return done();
      if (Date.now() - startedAt < WAIT_MS) frame = requestAnimationFrame(tryFocus);
      else done();
    };
    frame = requestAnimationFrame(tryFocus);
    return () => cancelAnimationFrame(frame);
  }, [pathname]);
}
````
